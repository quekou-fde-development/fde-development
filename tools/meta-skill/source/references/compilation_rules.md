# 编译规则明细

按 SKILL.md 第 1–9 步读取对应节。运行接口、工程闸与退出码按 SKILL.md 及 contract_ir.md 执行。

## 第 1 步 · 锁定目标函数与选择环境

先写死这份 skill 优化什么。缺目标函数，后面判据全退化成无法收敛的描述。填满下表，缺项不得进第 2 步：

```text
最终产物：     这份 skill 跑完交出什么
成功条件：     什么算做对
失败条件：     什么算做砸
选择环境：     谁用结果 / 谁判结果 / 结果进什么场景
可接受复现率：  100% 规则复现 / 还是企业场景复现 80-90% 关键工作即够
当前证据类型：  显式规则 / 历史案例 / 成功失败差异 / 专家陈述 / 相关性线索 / 反例（逐项标置信度）
人类裁决出口：  接收者是谁 / 他要决定什么 / 不读源码时最少需要知道什么 / 最短回复是什么
workflow_mode： artifact / stateful（判据见 stateful_workflows.md §1 · 双轴分类）
runner topology：入口文件、命令选择器、工作目录参数、handler 绑定方式、最终调用点
M8 binding：canonical_stage_runner / production_router_needing_adapter
```

允许用相关性与 likelihood 立判据，不得把相关性写成已证因果。不追求科学因果，只把命中率提到目标函数够用。

**入口诊断（先于填表 · 二值 · 不进则退）**：先判目标产物是不是 Skill 编译目标。

- 目标产物 = 带 `name + description`、会被调度器**再次触发**的持久 Skill 包 → 进本流程，且**执行段机械覆盖为强制条件**（见 SKILL.md §第 6 步），无次数豁免、无「先跑起来以后再补」。
- 目标产物 = 一次性答案 / 一次性产物（跑完即弃、不进调度器）→ **不进本流程**，输出「不是 Skill 编译目标」的诊断并交回，不编 SKILL.md。

成本在此处裁断：机械覆盖的成本该不该付，是「要不要做成 Skill」的问题；一旦判定做 Skill，机械执行层不得再降级。已决定做 Skill 后以「就用几次 / 成本太高 / 先简化」为由跳过机械覆盖 = 违反本步，第 8 步机械闸按缺件 fail。

> 第 1 步产物是蒸馏脚手架，不写进成品 SKILL.md（写进去 = 向 agent 叙述"我们优化什么"，违反命令式总则）。

## 第 2 步 · 切执行段与判断段

把整条工作流切成交替序列。逐项标类，不得留未标项：

- **执行段** = 步骤够清就能复现的操作，跑完留下可观测的阶段成果。
- **判断段**（旧称「判断节点」，v3.5 统一——判断有四相位内部结构，是有测度的段，非零测度节点） = 拿前面成果对照目标做判断，判断结果直接改变后续执行走向。

> **本体论权威源**：「判断段 / 执行段 / 段 / 测度 / 边」的第一性原理定义在 `meta-orchestrator/spec.md §2 结构模型`。此处为 meta-skill 运行时自包含的操作层复述，语义以 §2 为准；两处若冲突，改此处对齐 §2，不反向改 §2。

按此式排出全流程，每项一句话标类（招投标示例）：
```
1. [执行段]   读招标文件 → 生成整合信息
2. [判断段] 判该不该投 → 投进 3 / 不投出否决报告
3. [执行段]   按模板生成投标文件
4. [判断段] 判中标率是否过线 → ...
```

把切分结果标为 inferred：这一刀切错（判断段误当执行段、漏段）会让下游全部判据白挖且不自暴露。交第 8 步黑箱测专项核这一刀。

## 第 3 步 · 两类段各自展开：判断段挖三件套，执行段填六槽

判断段与执行段在本步对称展开——判断段展开成四相位小循环挖三件套，执行段展开成 operation 填六槽。任一类段展不开 = 该段未拆到位，回本步重挖；两类都展完才进第 4 步。

### 3A · 判断段展开四相位，定位并挖出三件套

把每个判断段展开成一个四相位小循环：

- **1A 检索**：取新信息 X。取什么由本判断段目标定，执行性，不挖判据。
- **1B 整合**：把 X 并入已有信息 R，得 X×R。
- **2A 生成**：基于 X×R 生成结构 C，把信念 B1 更新为 B2。
- **2B 审核**：用 B2 量 C，定过线与否，给下一段执行指令。

按相位定位三件套，逐判断段挖齐，缺一即判该段未拆到位、回本步重挖：

| 件 | 产出相位 | 挖什么 |
|---|---|---|
| **判断标准** | **1B + 2A** | 尺子本身——凭什么这么判，落到一条可复述规则，不许"看情况" |
| **触发钩子** | **2B** | 阈值 / 分界线，就地给一个具体数或具体线，不许"差不多" |
| **路由** | **2B** | 每个分支各去哪，逐分支写明去向 |

判断标准只产于 1B-2A（尺子成形），钩子与路由只产于 2B（拿尺子量）；2B 不自产标准，B2 由 2A 给。挖三件套按此分相取料，不在四相位平均用力。

每个判断段出一张卡：
```
判断段：该不该投这个标
  判断标准（1B+2A）：预估利润率÷投入工时是否过线 + 有无控标迹象
  触发钩子（2B）：    利润率 < 8% 或 识别到控标
  路由（2B）：        过线 → 进应答表生成；不过 → 输出"放弃+理由"
```

### 3B · 执行段展开 operation，填六槽

每个执行段的每个动作标**恰好一个 operation**，取自封闭词汇表 8 类（`acquire / filter / map / join / partition / aggregate / render / handoff`，语义与判别问句见 `references/contract_ir.md §2` [OBL:OPERATION.VOCAB]）。标不出 = 该段未拆到位，回第 2 步重切；词汇表外登记 `custom`，默认 FAIL，启用须独立 golden + 定向 mutant + 来源锚三条件全在位（`contract_ir.md §5` [OBL:CUSTOM.EVIDENCE]；三条件说的是**东西**不是**键**，第 8 步 M9 逐条实跑验：anchor 真存在、路径不逃逸、独立 golden 与定向 mutant 真落在指名断言上）。

标定 operation 后逐段填六槽，缺一即该执行段未拆到位、回本步重填：

```text
动作：      具体动词 + 明确对象
可达接口：   本动作靠什么执行——脚本可直调的接口（命令 / API / 文件读写），或 GUI/人类 handoff；stateful 卡必须含唯一 `path.py::symbol` 生产入口
依据：      输入与规则从哪来——现场规则本体，或可解析指针（文件 §节 / 上游段产物）
产出：      交出什么 + schema + 落到哪（相对路径，禁绝对路径）
值域：      产物各字段的合法取值范围（枚举集 / 数值区间 / 正则 / schema 引用）
断言：      本段 operation 的最低强断言族逐条列出 + 各条 tier（0/1/2）
副作用：    run_dir_only / shared_state / external_system / scheduler / lock 五选一
```

槽名与总则四槽**逐字一致**（动作 / 依据 / 产出 / 值域），不另起别名——第 8 步 M7
是按这四个字面量做机械匹配的，卡里换个说法（"依据源"、"产物"）会让填对的步
被闸判缺槽。前五槽 = 总则四槽 + **可达接口**：可达接口是执行段独有的一槽，四槽
俱全而动作不可达的空心段，是 08-05 双包实测暴露的缺口（GUI 取数的动作、依据、
产出、值域都写得出，脚本仍然执行不了）。第六槽是机械覆盖的登记面：断言槽的内容
由 operation 机械决定（`contract_ir.md §3` [OBL:ASSERTION.MINIMUM] 最低强断言族表），**不是编译者自由
发挥**——填的是查表结果，填不满即该 operation 标错或该段该拆。

每个执行段出一张卡：
```
执行段：按国家筛单
  动作：       从 s1 导出表删掉非中国发货单
  可达接口：   脚本读 s1_export.json，写 s2_filtered.json
  依据：       本 skill §第 2 步保留规则（现场规则本体）
  产出：       s2_filtered.json {orders[], deleted_us, deleted_blank} → runs/<run-id>/
  值域：       orders[].country ∈ {中国发货}；deleted_us / deleted_blank ∈ 非负整数
  断言：       output⊆input(T1) + predicate replay(T1) + excluded count/set(T1)
  副作用：     run_dir_only
```

**执行段缺料熔断（对称第 5 步判断段缺料）**：六槽任一填不出——不知具体动作 / 接口不明 / 依据既无规则也无指针 / 产出无名无 schema 无落点 / 值域说不出 / operation 标不出致断言列不出——**标红"此段执行层缺料"、回流素材端补料**，禁止用抽象动词硬编冒充确定动作。

把 operation 标定结果与三件套一并标为 inferred：operation 标错会让最低断言族查错表，断言全绿而错误照过，且不自暴露。交第 8 步黑箱测与定向 mutant 双核。

### 3C · stateful 包再切 effect boundary

每个卡片式及编号/列表式执行单元都须显式声明 `副作用`；缺失时 fail-closed。workflow_mode=stateful 时，在 operation 切分之外逐项列出外部或共享状态效果。operation 继续描述数据变换；effect boundary 按 `stateful_workflows.md §2 · stateful_contract schema` 描述副作用与恢复。两张表不得互相替代。

在写 assertions 前对 runner 做 topology preflight。M8 的 canonical 共用入口要求 `--stage`、`--run-dir` 与实际索引并调用的 stage 字典 dispatch；生产 CLI 使用 `argparse` subparser callback、`set_defaults(function=...) → args.function(args)`、if/elif 或其它路由时，保留生产入口并另建 verification adapter。adapter 只做参数归一与真实 handler/API 调用，不复制业务逻辑，并在包根 `runner_binding.json` 逐 stage 绑定真实生产文件 SHA 与 `runpy` / `module_call` 可达调用。`assertions.json` 只声明判据，不能补出缺失的入口绑定。

每个 effect boundary 先画最小状态时序：intent/checkpoint → effect → receipt/readback → commit → unlock。再分别标出进程在每条边后中断时的恢复入口。无法给出稳定 idempotency key、独立 readback 或 unknown-state 裁断时，标红“此效果不可安全自动重试”，停止自动化范围扩张并回流素材端。

锁 owner 使用 attempt identity；logical target 只负责业务去重和积压排序。两者复用同一值时，跨次执行无法区分陈旧 owner 与新 attempt，按结构缺口返回第 1 步。

## 第 4 步 · 判据来源，分流 index-mode / extract-mode

对第 3 步每条判断标准，先判它有没有现成权威源的家，再决定第 6 步怎么落：

- **判据已有权威源的家**（如记忆系统的规则文件、已成型的判据库）→ **index-mode**：本步只**定位**到判据所在的具体节，不在 skill 里重挖、不复制本体。第 6 步写精确指针。
- **判据无家、须从素材现挖** → **extract-mode**：本步按下方差集 + 六类来源挖出判据本体。第 6 步内联（因为没有别的家）。

误把 index-mode 判据当 extract-mode 挖出来内联 = 制造复制体，违反目标系统单一权威源，第 8 步白箱审 A1 会判 fail。先分流再挖。

**extract-mode 挖判据——判断标准来自差集，不来自单边共性：**

一条特征要成判据，必须**成功案例普遍有、失败案例普遍无**。成功共性单看会混入伴随特征（中标标书都用蓝封面，但废标也用蓝封面 → 蓝封面出局）。标准间一致性查不出伪判据（伪判据内部可自洽），只有比对失败案例的差集能切掉。共性与差集是同体两面：真共性的定义里已含"失败无"，写进 skill 时显式写成差集运算，防实现时滑回"只扫成功找重复"。

按此出判准卡：
```text
判准：       （成功有∩失败无 的那条特征）
来源：       显式标准 / 目标函数反推 / 成功-失败差异 / 反例边界（标出处）
程度阈值：    不止有无二值——成功侧强到何值才算数，给线
证据：       支撑这条的正反案例
反例：       看似合标准却失败 / 看似不合却成功
适用边界：
置信度：
更新条件：
```

允许相关性判准，标注为相关性、不伪装因果。

## 第 5 步 · 缺料时的不完全信息推理

第 3-4 步挖不动时，不得停、不得编通用答案。按 loop 走，推理受素材约束：

1. 追问 what：这个判断段处理什么对象 / 事实 / 输入。
2. 追问 why：这事实为何影响判断，与目标函数什么关系。
3. 追问 how：让这判断重演一次，证据怎么走到结论。
4. 生成 2-4 个事实假说或判准假说。
5. 每个假说写预测：成立则素材应出现什么证据，不成立应出现什么反证。
6. 选当前解释力最高一条，不平均对待。
7. 派 2-3 个 sub-agent 独立判：只给原始素材和问题、不给主模型结论，各自判哪个假说最合素材。
8. 多路收敛 → 立为 inferred 判准；分歧明显 → 回第 4 步重拆。
9. 所有推出的判据标 inferred + 置信度 + 更新条件。

案例稀疏到连差集都抽不出的判断段（罕见致命点、全新无先例）：不得用收敛假装拿到判据。标红"案例不足 / 判据 inferred / 低置信"，回流素材端补正反案例。补料前留成人类判断点，写清判断者需先看到什么。

## 第 6 步 · 编码成 SKILL.md

### 6A · 人类汇报契约

凡 skill 会向人报告结果、请求授权或等待裁决，都要在正文写清终态汇报契约，并在黑箱验收中单独验证。汇报顺序固定为：

1. **结果**：用一到三句说明发生了什么、哪些目标已实现、哪些没有。
2. **影响**：说明现状会怎样影响下一步；不要先抛状态码、文件结构或执行阶段。
3. **需要你决定**：每项只问一个问题，列出互斥选项并明确推荐项及理由。
4. **选择后果**：分别说明批准、拒绝或暂缓会改变什么。
5. **最短回复**：给出可直接复制的最短答复；无需人类把内部状态翻译回系统动作。
6. **核验依据**：路径、命令、锁、哈希、receipt、stage、内部 verdict 等放在末尾；无法省略的术语在首次出现处用一句自然语言解释。

无裁决项时省略第 3–5 项，仍须先给结果与影响。执行未完成时，首段必须说明停止点、已发生的副作用和恢复入口；不得使用完成口径。标题与摘要要让不了解实现的人单独看懂，禁用裸状态码、字段名或结构性术语充当标题和结论。

把机器终态与人类汇报分成两层：机器层保留精确枚举、收据和退出码；人类层翻译其意义与动作。两层须指向同一事实，机器层不得直接替代人类层。

把第 2-3 步的结构落成文字，按总则纯命令式写：

- **index-mode 判据** → 写**精确指针**，指到权威源具体节，不抄本体。
- **extract-mode 判据** → 内联写全（无别的家）：执行段按总则四槽契约写——动作（动词 + 对象）/ 依据（现场规则或可解析指针，二选一）/ 产出（交出什么、落到哪）/ 值域（合法取值范围，写到脚本能判的颗粒度），外加格式校验与失败处置；判断段三件套写全。问句照总则问句闭合律写：逐答案给分流，不得以开放问句收尾。
  - **执行段缺料熔断**（对称第 5 步判断段缺料）：素材填不齐四槽任一（不知具体步骤 / 依据既写不出规则也给不出指针 / 产物无名无落点 / 值域说不出）时，**标红"此段执行层缺料"、回流素材端补料**——禁止用抽象动词（"处理"、"对照"、"按判准做"）硬编冒充确定动作，禁止用开放问句（"搞清楚 X"）冒充步骤。空心执行段过不了第 8 步内部逻辑审「执行段可执行性」，此处硬编 = 把 fail 推迟到验收，不如就地熔断。〔诊断源：strict_20260709 纯描述语料无执行层血肉，八段本应报缺料、实际硬编空心 bullet〕
- **inferred 判据** → 标 inferred + 置信度 + 更新条件，不写成硬规则。
- **人类判断点** → 写"此处交人判断" + 列判断者所需信息，不写成假规则。

两条收尾：
- **自由度配脆弱度**：一步多解、靠上下文 → 给原则让执行者自走；一步易错、须固定顺序 → 写死命令。
- **依据熔进命令**：要讲依据时熔成命令的条件或后果，不堆描述、不堆无源禁令。"不要做 X"仅当执行者真会自发做 X 才留，否则删。

**成品**：一份 SKILL.md + 一个 `scripts/` + 一份 canonical contract（默认包根 `assertions.json`；仅在同名原生回归件或布局约束下显式改址）。正文 ≤500 行，超了把细节挪 `references/` 一级直链、正文留指针。

## 第 7 步 · 触发行为与失败分流

7. **行为闸（触发地面真值 · 架在 judge 之上，不替代 judge）**：judge 是单 skill 二元判定，只筛 description 文字有没有把该触发场景写全，触发力强弱它判不出。真实触发靠对象层实测——把目标 skill 连同语义相邻的若干 skill 的 description 一并列给 clean-context sub-agent，给一句用户话问"调哪个 / 不调"，不告诉它在测什么（"评估该不该触发"的元层问法会让模型从主题推意图、虚高放行）。取 should_trigger 与 near-miss 各若干句，关键句多轮看一致：落对目标 = 过，落错邻居 / 漏触发 = fail。**哨兵守卫**：测试集塞一条已知错域 / 缺该场景的 description，断言行为闸必判它 fail；判过 = 行为闸自己失灵（竞争集没摆够 / judge 噪声），先修测试再信读数。**产出落盘**：判定写 `trigger_eval/behavior_gate.json`——每 query 记 `query / expected_skill / routed_to（各轮）/ consistent / pass`，与 judge 的 result.json 并列，可复现可审计，禁止只在对话里眼看收敛。
8. **不过的分流（judge 或行为闸 fail 才走 · 按失败类型选修法、非一律改写 · 至多 5 轮）**：先认失败类型再定修哪：
   - **漏触发**（should_trigger 没触发）→ description 没写出该场景 → 改本 skill description 回跑。
   - **抢错邻居 / near-miss 落错家** → 两 skill 边界问题 → 裁该收窄自己还是放宽邻居（**可能改的是邻居 description、不是本 skill**），判不清交人定归属，不默认改自己。
   - **哨兵判过** → 行为闸自己失灵（竞争集没摆够 / judge 噪声）→ 修测试集，**不碰 description**。
   **动作：** 定为改写时执行 `prepare --version rev1 --rev-desc "<改写>"`，再派 sub-agent 判并执行 `score --version rev1` **依据：** 本步失败类型分流与行为闸结果 **产出：** rev1 判定与 `best_description` **值域：** 至多 5 轮，best 仅在同一冻结数据集内比较；另留封存测试集评估泛化。

## 第 8 步 · 内部逻辑与独立黑箱

### 第二道 · 内部逻辑审（必跑 · 逐项 pass/fail · 交 LLM 判）

任何 skill 都有内部判断段逻辑与执行段动作，本道必跑。逐项过四项（判断段维度：局部判准 / 全局判准 / 命令式复查；执行段维度：可执行性）：

**局部判准一致（逐判断段）**：每个判断段的判断标准必须展开成四环链，缺环 / 断链 = fail：
```
  目的     ：本判断段服务第 1 步目标函数的哪一条（为达成什么而判）
→ 判断标准：基于该目的，凭什么判（一条可复述的尺子，禁"看情况"）
→ 判断指标：基于该标准，落到什么可测的数 / 线 / 信号（禁"差不多"）
→ 路由     ：该指标取值如何映射到各分支去向（逐分支写明）
```
自洽检验逐环验：目的真能生成该标准 / 标准真能量出该指标 / 指标真能驱动该路由——任一环接不上 = fail（标准与目的脱节 / 指标量不出标准 / 路由不依指标）。

**执行段可执行性（逐执行段 · 与判断段四环链对称 · 按总则四槽契约验）**：判断段验"判得对"，执行段验"做得动"。每个执行段的每个动作必须落成确定操作，四槽齐、缺一即 fail：
```
  动作   ：一个具体动词 + 明确对象（禁裸抽象动词："处理"、"对照"、"整合"、"按判准做"、"做差分"——问不出"具体对什么、怎么做"即空心）
→ 依据   ：本步输入与规则从哪来——现场写出的规则本体，或可解析指针（文件路径 / 权威源 §节 / 上游段产物）二选一；凭空输入、死链指针、"自行搞清楚" = fail
→ 产出   ：点名本步交出什么 + 写到哪 / 交给谁（文件 / stamp / 下游段）——只有落点没有交付物名、或无归宿 = fail
→ 值域   ：产物的合法取值范围（枚举 / 区间 / 正则 / schema）——写不到脚本能判的颗粒度 = fail
```
判据 = 一个 clean agent 只读这句能不能无歧义执行。命中任一即 fail：动词无对象（"处理数据"）/ 依据缺位（"对照 schema"但没说 schema 在哪；指针指向不存在的节）/ 操作无步骤（"做差分"但没说怎么做）/ 产出无名或无落点 / 值域缺失或不可判 / 以开放问句收尾（"搞清楚 X 对不对"而无逐答案路由 = 欠定判断冒充执行步）。**执行段是命令句但不可执行 = 本项 fail**（命令式复查只验句式、本项验可执行性，两者正交，都要过）。〔诊断源：strict_20260709 八段执行节全是无来源无落点抽象 bullet、却过了命令式复查〕

**全局判准一致**：每个判断段的"目的"都回溯得到第 1 步全局目标函数（无悬空段）；段间判准不互斥（A 段判准不与 B 段冲突）；无死结（改好甲必违乙 → 第 6 步迭代 loop 不收敛）；无对象挂起（每个被判对象都有来源 + 去向）。

**人类裁决出口**：从正例、失败例和待裁例各取至少一条，只给独立判定者最终汇报。判定者不得查看源码、日志或术语表；须能准确复述结果、影响、待裁问题、推荐项、各选项后果与最短回复。任何一项依赖猜测、内部状态码或工程知识即退回第 6 步。

**命令式复查**：检索元层叙事词（"目的""我们在做""这是为了""本 skill"）→ 命中 = fail；逐句判命令句（令 agent 做什么 / 怎么判 / 走哪）vs 描述句（叙述是什么 / 为什么）vs 问句 → 描述句 = fail；问句仅当以判断段形态出现（带逐答案分流承接、答案集穷尽）才合法，以开放问句收尾（无路由承接）= fail；依据须熔进命令的条件 / 后果，不另起描述句。

### 第四道 · 黑箱测（真跑 · 主 agent 派 sub-agent 自己裁断）

轻档 smoke 必跑两轮（Round 1 覆盖 + Round 2 分歧前哨）；重档收敛高 stakes 才触发。三者全派独立 sub-agent（各 clean context、互不可见、不给主 agent 结论）；skill 含不可逆动作 → 令其 DRY RUN（声明动作不真做）。

**轻档 Round 1 · 覆盖（地板 · 必跑）**：派 3 个 sub-agent，各跑**一个不同的真实任务**（3 路 = 3 个独立任务，分头覆盖不同判断段 / 边界）。各自产出逐判断段路由结论 + 卡壳清单（(a) 顺指针读权威源仍判不动 / (b) skill 该说没说 / (c) 执行段某步不知怎么做 / 去哪读输入 / 产物落哪 / 撞上无路由承接的开放问句——执行层可执行性卡点）。主 agent 据报告裁断：跑得通否 / 路由顺否 / **执行段每步能否无歧义执行**（(c) 类卡点 = 内部逻辑审「执行段可执行性」在行为层的复现，回第 1-3 步或就地熔断补料）/ 抓到哪些内逻辑审漏掉的执行 bug；必读 transcript 分清是 skill 错还是 grader 拒了合法解。

**轻档 Round 2 · 分歧前哨（地板 · 必跑 · 单向否决）**：从 Round 1 已跑的任务里挑一条复用（默认取判断段最多 / 最吃边界的那条；自己判，不为凑「新任务」硬造个更烂的、也不图省事随手抓——复用本身不是偷懒，造烂任务才是），补派 2 个 sub-agent 跑同一任务（并入 Round 1 该任务的 1 跑 = 同任务 3 路）。逐判断段比对 3 路路由，按结果分流：
- 任一判断段 3 路走不同分支（裂开）→ **fail，回第 1-3 步**：该段判据没挖透 / 第 6 步该写死处配了自由度。
- 3 路全收敛 → 记为**「未测出分歧」**，禁记「可复现 / 通过」；本轮无 reference、无 baseline，同输入 3 路一致也可能是判据错或模型共享偏置致的一致错，正确性背书归重档。

Round 1 每判断段只跑一次、测不到同输入的路由抖动；Round 2 专抓这层方差缺陷（判断段不确定 / 该写死没写死的协议漏）。Round 2 是重档的无参考前哨：裂开即回流，省下重档构造 reference / held-out 的人力。

**重档收敛（条件：skill 高 stakes 才触发）**：
`skill 判错担责 / 要求接近 100% 复现率（接第 1 步 可接受复现率）→ 追加下沉 references/verification.md §黑箱测·重档（收敛测：同任务 × 3 路 + pass^k + 已有案例库切 held-out）。`
方法学（任务集构造 / 测试集来源降级链 / pass^k / 阈值 / DRY-RUN 特化 / 裁断追因）全在 verification，本步只决定该不该触发它。

**异族盲跑（重档要件 · 弱模型臂）**：重档触发时，至少一路用与编译者不同族 / 更弱的模型跑。同族同强度的自审对「复制改造类不一致」系统性失明——编译者能补全的隐含前提，弱模型补不上，正好把 skill 里靠上下文默认撑着的欠定处暴露出来。弱模型臂卡住的点即欠定点，回第 3 步补槽，不得以"模型不行"结案。〔诊断源：v1.1 轮 opus 亲编自判全绿 → sonnet 异族盲跑挖出 4 处漂移〕

## 第 9 步 · 迭代比较

将失败分叉追到原始输入、判断标准或执行槽，修复相应段后，用同一冻结任务集比较候选与现役基线。派独立 comparator（agents/comparator.md）双盲比较产物，再派 analyzer（agents/analyzer.md）揭盲追因。保存比较、分析和 history 记录。将用于候选选择的数据视为验证集；泛化结论另用未参与选择的封存测试集。连续两轮 tie/lost 时停止并报告剩余限制。
