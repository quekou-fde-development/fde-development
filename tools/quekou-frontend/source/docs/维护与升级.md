# 维护与升级

公司指定一名工具包维护人，统一管理 design/tokens.json、组件包和版本发布。项目负责人负责客户口径与验收；普通同事在独立客户项目中使用。

## 公司母版验证

环境：Node 22.12–24，npm 10+。建议 Node 24；生成共享 ZIP 的维护人另需 Python 3（仅使用标准库）。同事运行和创建客户项目不需要 Python。发布验证的具体版本见 RELEASE_AUDIT.md。

1. npm ci
2. npm run check
3. npx playwright install chromium
4. npm run test:browser
5. npm audit --json（需要连接 npm 官方源）
6. npm run release

浏览器检查自己在 4197 端口启动构建产物并结束服务，不使用日常预览端口。
可指定 WORKBENCH_BROWSER=webkit/firefox；先安装对应 Playwright 浏览器。机器已有 Chrome 时可设置 WORKBENCH_BROWSER_CHANNEL=chrome。
自动测试覆盖的是套件及代表性数据，不是每个客户任意改动后的全部情况。客户项目另按上线清单验证。

## 产生新客户

node scripts/create-client.mjs --name "客户名" --out "clients/客户名" --style 6

可附 --business、--entity 及四项风格参数。禁止目标已存在；脚本不覆盖或合并旧目录。
首次在客户目录 npm install 生成客户自己的 package-lock.json；以后用 npm ci。版本锁定文件随客户项目保存。只有三个运行依赖与两份缺口本地包，不连接公共的 @quekou registry。
客户目录不依赖公司母版的绝对路径；保留 vendor 文件夹即可重新安装。

## 现有项目接入

先核对 React 18、Tailwind 3 和现有页面需求。把两份同版本 tgz 放入项目 vendor，再将 @quekou/theme 与 @quekou/ui 同时指向这两份本地包。导入 tokens.css 和 styles.css；以 ThemeProvider 包住页面。详见 packages/ui/README.md。
不得为了接入覆盖现有客户项目；非兼容技术栈先评估迁移成本。

## 发布与回退

- 不改已发出的 ZIP。修复后升新版本，并说明影响范围。
- themes、ui 版本必须一致；先在一个客户副本验证再推广。
- company ZIP 使用白名单打包，排除 node_modules、客户目录、历史缓存和环境密钥。
- 归档含 SHA256SUMS.txt；核对脚本 verify-release.mjs 会验证文件数量、路径和内容摘要。
- 每个客户保留原版本包和 lockfile；回退恢复原包及 lockfile，再执行 npm ci 和检查。
- 从公司认可的当前版本入口取包，SHA256 用于检测传输损坏；若压缩包和摘要同时遭到替换，摘要本身不能证明来源。

## 团队协作

内部网盘用于分发版本；同一客户的多人编辑使用公司指定的私有代码仓库。不要并发修改一个共享网盘工作目录。
共享整个项目包含的 .agents/skills 与 AGENTS.md，不修改每个同事全局的 Codex 配置。不需要额外插件安装。
