# 缺口工作台 · 从这里开始

这是一套制作企业后台页面的公司工具箱。它把缺口的颜色、页面结构和常用组件固定下来，让你向 Codex 说业务需求就能开始做页面。**它包含前端工具与材料；真实账号、业务数据库和上线服务需按项目接入。**

你只需要做三件事：说明要解决什么业务问题、查看页面、决定是否符合实际。文件和安装由 Codex 处理。

## 现在就开始：你的第一条指令

你现在已经在这个工具包所在的 Codex 项目中。复制发送：

> 使用这套缺口工作台工具包，帮我创建一个名为“我的练习工作台”的独立练习项目，放到 clients/我的练习工作台，使用 6 号风格和缺口品牌色。先保留空数据，帮我安装、检查并打开总览、列表、详情、设置四个页面。我不写代码，请一次只让我完成一个验收动作，并解释我在页面上看到的内容。

如果该目录已经存在，告诉 Codex“继续现有练习项目，不要重新创建”。

看到页面后，先点“业务列表”，再点“工作区设置”。改一个工作区名称、保存，看看顶栏变化。这次保存仅是界面演练，刷新会恢复初始名称；不是正式业务保存。

## 第一次在另一台电脑使用

1. 安装并登录自己公司的 Codex 账号。
2. 把收到的共享 ZIP **完整解压**到一个准备长期保存的文件夹。不要在压缩包中直接打开文件。
3. 在 Codex 的项目区域添加本地项目，选择解压出来、包含 START_HERE.md 和 AGENTS.md 的那一层文件夹。若项目已经存在，可在项目菜单的“编辑项目 / Edit project”里“添加文件夹 / Add folder”，并把该文件夹设为主要目录。不同版本按钮文字可能略有不同。
4. 在这个项目里新建对话，发送上面的练习指令。不要只把 README 拖进一个普通聊天；Codex 需要能操作完整项目文件夹。
5. 等 Codex 返回可点击的页面地址。页面打开才算完成第一次启动。缺少运行环境时，让 Codex检查其自带运行时；若仍无法启动，把它报告的缺口交给公司技术同事处理。

如果没有自动识别技能，在同一项目里发送：“先读取 .agents/skills/quekou-workbench/SKILL.md，再按它执行我的请求。”不需要先购买额外 UI 产品，也不需要 API key 才能看本地页面。

## 为真实客户创建页面

把下面的方括号内容替换，再发给 Codex。暂时不知道的写“待确认”。

> 使用缺口工作台工具包，为【客户名称】创建一个独立客户项目。使用 6 号风格和缺口品牌色。业务是【例如制造业项目交付管理】，使用者是【项目经理】，每天需要【看延期、找负责人、查看验收证据】。核心对象是【项目】，四项指标是【项目数、延期数、本周到期数、已验收数】。需要总览、列表、详情、设置。先读取 NEW_CLIENT.md；缺少的数据口径先问我。完成后打开页面给我验收，并记录下次继续的位置。

不必理解英文参数。不知道选什么时，先用 6 号；7 号偏深色玻璃层次，10 号偏紧凑、连续处理工作。改变风格不会替你定义业务规则。

## 怎么提出修改

用“哪个页面 + 什么问题 + 希望如何处理”描述：

> 在业务列表中，我要先看到负责人和计划完成日期。把“逾期”定义为计划日期早于今天且尚未完成；这个定义先和我确认。保留缺口配色与既定页面结构。完成后用两个明确标注的演示案例给我检查。

> 先不要接真实系统。请把数据加载、没有记录、保存失败三种情况分别展示给我看。

不要只说“高级一点”。说明“我要更快看出哪几个项目需要我处理”更容易得到合适结果。

## 怎么验收：你亲自做五件事

- 看：客户名、字段、金额和状态是否符合业务；模拟信息有没有明确标注。
- 找：用一个你知道的对象搜索，看看筛选和排序是不是对的。
- 点：从列表进入同一个对象的详情，再返回；不能跳成另一个对象。
- 改：输入错误或留空时是否有提示；保存后刷新是否还在，必须按双方约定验证。
- 问：让 Codex 报告“真实接入了什么、只是演示什么、还有什么没验证”。

页面好看不等于可以上线。准备让员工正式录入客户信息时，按 docs/上线验收.md 由项目负责人和技术负责人确认。

## 下次如何继续

重新打开同一个客户项目文件夹，发送：

> 继续这个客户工作台。先读取 AGENTS.md 和 PROJECT_BRIEF.md，告诉我已经完成什么、还缺什么；启动本地预览，返回当前可打开的地址，然后继续【这次要改的内容】。

本地预览地址只在服务运行时可用。关闭 Codex/电脑后页面打不开，不代表文件丢了；让 Codex重新启动即可。127.0.0.1 指你自己电脑，发给同事不能让对方看到你的页面。

## 怎么分享给同事

把公司共享 ZIP 和这份手册一起放进公司内部网盘或发给同事。建议只维护一个“当前版本”入口；每位同事完整下载并解压后，按首次使用步骤操作。

可直接转发这段说明：

> 这是杭州缺口工作台工具包 1.0.0。请完整解压，在 Codex 中打开包含 START_HERE.md 的文件夹，按手册里的“我的练习工作台”指令完成第一次演练。以后每个客户建独立项目。不要把 localhost 地址当作共享页面；不要把演示数据当真实经营数据。遇到问题请附项目名称、版本、复现步骤和报错原文。

“统一工具”与“共同编辑同一个客户项目”不同。共同编辑时，由项目负责人指定一个公司私有代码仓库和维护人，大家按该仓库协作；不要多人覆盖同一个网盘文件夹。当前交付没有替公司创建线上仓库或发布网站。

## 常见卡点

| 看到什么 | 发给 Codex 什么 |
|---|---|
| 不知道选哪个文件夹 | “帮我确认当前目录有没有 AGENTS.md 和 START_HERE.md；没有就告诉我应该选哪一层。” |
| 页面打不开 | “检查本项目预览是否运行、端口是否冲突，重新启动并返回实际可用地址。” |
| 找不到缺口技能 | “读取当前目录 .agents/skills/quekou-workbench/SKILL.md，按说明继续。” |
| 已存在同名文件夹 | “保留现有文件，继续已有项目，不要覆盖。” |
| 安装报错 | “检查 Node/npm、网络和依赖锁定文件，先给我明确原因；不要随意更换技术栈。” |
| 想发给客户看 | “先整理演示版和模拟数据说明；评估公司批准的分享方式，给我可以审阅的版本。” |
