# 调研报告（对内）

## 如何填写

- 本报告由 PM 在调研后出具，交给架构师作为架构设计依据。只记录查到的、看到的、客户说的及明确标出的整理判断；客户原话标「口述」，未知写「未确认」，不把方案主张写成客户事实。
- 需求分三层衔接：1 次需求确定行业背景；2 次需求确定组织结构、数据环境、初步业务流与初步生产线；调研进一步确定资金流、业务流、信息流、数据流、生产线、本次场景及场景内工作流。
- 信息流是组织结构上的信息流向，较抽象；数据流是系统里的记录流向。两者相关但不必一致，不一致处必须在第 5、6 节分别记录并单列差异。
- 用【观察】记录亲见事实，用【问】记录原话或转述，用【取样】记录材料，用【测量】记录现场数据。已有材料可直接附路径并标明对应章节。
- 没有该场景写「不适用：原因」；未知写「未确认：待向谁或取什么材料确认」。拍照、录屏、导出和取样前先记录许可范围，共享副本按需脱敏。
- 先完成事实与证据整理，再进入架构设计。开发计划、架构设计（含架构图）和解决方案为送审三件，范围与报价作附件；spec 在审核通过后按需编写。

## 12. 按 AI 能力边界拆解工作流

第七节拆出来的每一步，逐条判断：这件事交给机器能不能做、能做到什么程度。

### 12.1 机器能做的四类事

| 类 | 什么意思 | 举例 |
|---|---|---|
| **1 · 定时任务** | 到点就做，不看内容 | 每天早上八点导一次库存、每周末生成一张对账表 |
| **2 · 查询、检索** | 你要什么，它去找出来 | 查这个客户上个月下了几单、把某份合同找出来 |
| **3 · 生成** | 3.1 生成计算：算数、汇总、比对，出数<br>3.2 生成文案：写通知、写回复、写说明 | 算出这批料的成本；写一封催款函 |
| **4 · 判断、识别** | 看一眼，判断这是什么、对不对、归哪一类 | 这张单据是不是重复录了；这条投诉属于哪一类 |

**四类之外的事，机器直接做不了**：改变物理过程、改变人的想法、改变法律责任归属。要做的，必须绕一层信息才能碰到——绕不出来的，写「做不了」。

### 12.2 每一处 AI 工作都要配两样东西

机器只靠模型是做不成事的，每一处都要配：

- **知识库**：这件事要用到的资料、规则、历史案例，从哪来、谁维护、多久更新一次
- **Skill**：这件事具体怎么一步步做，写成可以照做的流程

两样缺一样，这一处就只能做「给人参考」，不能做「替人干活」。

### 12.3 逐条判断表

| 编号 | 工作流步 | 这一步在干什么 | 属哪一类（1／2／3.1／3.2／4／做不了） | 为什么归这类 | 配什么知识库 | 配什么 Skill | 做到什么程度（给人参考／替人做完／替人做完还要人签） | 错了怎么发现 |
|---|---|---|---|---|---|---|---|---|
| | | | | | | | | |

**几条判断的参照**（写得粗，后面细定）：

- 定时任务最容易做，也最容易白做——先问这件事到点做，有没有人真去看。
- 查询检索的关键不在能不能查，在**数据在不在、权限给不给**。这两条过不了，这一类整条作废。
- 生成计算看**数从哪来、公式认不认**；生成文案看**写完了谁签字发出去**。
- 判断识别最难。现场要问清：老师傅看什么下判断、判断错了怎么发现、错了以后谁承担。答不出这三条，这一类只能定位成「辅助」。
