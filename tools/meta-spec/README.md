# Meta Spec

读取明确版本的客户分析A、解决方案、来源与技术约束，使用内置的需求登记、流程拆解、概念、用例与数据推导方法，形成B组九份候选技术设计。项目架构师提出技术可行性，FDE编制独立开发计划，PM将解决方案与技术材料作为一套方案一次送审。

[阅读 Skill](source/SKILL.md) · [下载 ZIP](meta-spec-10.19.zip) · [查看验证说明](source/verification.json)

各类客户统一先形成解决方案，再生成技术架构，最后由总架构师一次审核商业可行性、技术可行性及整体一致性。产品决定明确后可生成B；缺少业务规则、权限、信息去向或关键交互时先澄清。尚缺独立计划与技术可行性判断时可先形成B，正式整套送审前须补齐。计划沿[现有模板](../../handbook/02-project-management/templates/04-development/开发计划模板_10.08.md)填写。

客户分析A记录现状及来源，产品方案说明拟实现的改善与工作方式，B将其落实到技术设计；三者按明确版本关联。产品或技术变化需同步受影响材料，核对整套一致性后重提。整体审核通过并落实启动与开工条件后实施，已签验收文件保持固定。

10.19更新送审接口与方法入口说明；确定性渲染器、九份写作参照及核心推导方法沿用既有版本。安装以ZIP为准，解压后的`meta-spec/`为安装根；仓库`source/`与安装包逐项一致。本次仓库发布不安装到运行宿主。

本轮验证范围与实际结果记录在`verification.json`的`single_review_checks`。方法审计、输入缺件时的停止行为、材料交接与机械检查分别记录；未生成的九份文件、未实测的平台能力和未执行的宿主安装不得视为通过。

历史四案例属于frozen-v14／10.09.1：借用11/11、客户12/12、巡检9/13、培训报名16/17。后两者的权限、输入约束或汇报缺陷仍保留，不能由本轮流程调整推定已修复。10.15.1、10.16及10.17的历史接口验证见同一验证文件。本轮结果不证明跨项目重复生成、真实客户或目标宿主运行通过。
