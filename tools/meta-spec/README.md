# Meta Spec

以明确版本的客户分析A（业务流、整体架构图及graph）、方案文档、客户类别、审核状态、调研证据和技术约束，形成B组九份候选开发设计。项目架构师提出技术可行性，PM组织总架构师审核。

[阅读 Skill](source/SKILL.md) · [下载 ZIP](meta-spec-10.17.zip) · [查看验证说明](source/verification.json)

A/B客户在方案审核通过后准备B及独立计划、技术可行性评估；C客户可提前准备开发材料，与方案一起送审。客户类别未知且方案未通过时先澄清类别；合并送审保留商业与技术两项审核结论。影响问题、产品、目标、范围或报价的差异先返回方案审核。B之外的独立开发计划沿[现有模板](../../handbook/02-project-management/templates/04-development/开发计划模板_10.08.md)填写。

10.17明确客户分析A先于方案形成，按A/B与C客户区分准备及送审条件；已有的问题与产品定义、AI采用依据、信息流和体验流结构保持，更新输入与审核交接接口，确定性渲染器及九份参照沿用frozen-v14。安装以ZIP为准，解压后的`meta-spec/`为安装根；仓库`source/`与安装包文件逐项一致。此次仓库发布不安装到运行宿主。

验证分开记录：10.15.1的接口检查见`verification.json`中`review_interface_checks`；既有四案例的九文档生成结果属于frozen-v14／10.09.1。历史上借用案例11/11、客户案例12/12、巡检案例9/13、培训报名案例16/17；后两者保留权限、输入约束或汇报缺陷。当前接口测试不证明这些历史内容缺陷已修复，也不证明真实客户、重复生成、目标宿主或平台执行通过。

10.15.1历史检查中，三类输入的阶段判断符合预期；生成的送审汇报仍出现暂缓后果遗漏、术语未解释和并行准备时点表述矛盾。该轮三路重复验证未完成。10.16仅核对Skill格式、输入与审核合同、源包一致性及引擎和参照字节完整性；完整九文档生成与宿主验收未重跑。10.17的格式、流程合同、源包及引擎完整性检查另见`verification.json`中的`review_sequence_checks`；完整九文档生成与目标宿主安装本次未执行。使用者仍需人工核对送审说明。
