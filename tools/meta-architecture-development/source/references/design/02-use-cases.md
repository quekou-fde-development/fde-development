# 用例文档(Use Cases)

本文档按真实角色和任务定义 Ticket 当前完整用例。所有用例必须在前后端可达，不允许出现未接后端的占位页面或旧路径 fallback。

## 范围与假设

- 平台管理端只服务平台管理员。
- 租户管理端服务租户管理员，负责项目级运营配置。
- 合作伙伴端服务 Partner，Partner 使用手机号登录。
- 业务系统通过项目密钥 HMAC 调用核销 API。
- 产品(Product)是外部唯一业务名词；内部 `TicketTemplate` 只是存储实现。
- 产品履约 JSON 是固定 JSON，不支持模板变量。

## 关键场景

### 场景 A：BotWorks 套餐卡券

1. 租户管理员在 Ticket 租户端创建项目。
2. 租户管理员创建产品，并将 BotWorks 套餐 JSON 粘贴为固定履约 JSON。
3. 租户管理员创建项目密钥，并把密钥配置到 BotWorks 租户后台。
4. 租户管理员生成券码。
5. BotWorks 用户在 billing 页面输入兑换码。
6. BotWorks 用项目密钥调用 Ticket reserve / confirm。
7. Ticket 返回产品固定履约 JSON，BotWorks 按 JSON apply package。

### 场景 B：Partner 运营

1. 租户管理员通过手机号邀请 Partner。
2. 被邀请手机号登录 Partner Portal 并激活身份。
3. Partner 查看产品、券码、配额、购买链接、订单、划拨、分享、导出，并在产品上下文查看资产聚合。
4. 所有 Partner API 只以 partnerId 校验当前手机号授权，不暴露 tenantId/projectId。
