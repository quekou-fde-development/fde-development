# 专项任务与工具入口

## 加载链（上下游）

**上游**：`../README.md` §小包目录；同版 HTML 手册 §附录 专项任务与工具。

在业务流中识别专项任务后，第 3 步明确数据对象，第 7 步明确调用契约，第 8 步固定工具入口；§12 完成接入，§13—14 按同一批业务样本联调和线上验证。下列三个入口为本版指定工具。

| 工作任务 | 使用工具与入口 | 需要准备的业务输入 | 应保存的结果与验收依据 |
|---|---|---|---|
| 生产排程、资源分配与约束优化 | [OctoPlanner](https://github.com/syngy-ai/octoplanner) | requirements、items、routings、resources JSON，以及规则和样本；ERP/Excel 数据先经适配层转换 | 排程、情景 diff、异常及 HTML 报告；检查 warnings、notModeled 和未排程原因 |
| CAD 图纸识别与参数提取 | [老马 drawings](https://laoma.syngy.cn/drawings) | 经授权的图纸与版本、需要提取的参数、单位及人工核对样本；文件格式和入口权限在项目开始时核对 | 识别结果与原图位置对应、缺失/歧义标记、人工确认记录；通过确认后供下游业务使用 |
| 爆品线索识别、选品与商品变化监测 | [SKU Radar](https://www.skuradar.ai/) | 目标站点/商品范围、时间窗、关注信号与人工复核规则；具体字段按登录界面或 CLI 帮助核对 | 商品/站点变化、报告及可用的 URL 快照或差异；保留来源、时间与业务人员复核 |

### 排产：OctoPlanner

OctoPlanner 是 Bun-first TypeScript 命令行工具。先读取官方 README、`package.json` 与命令帮助，记录采用的提交或版本。仓库给出的准备入口为 `npm install`，工作区初始化为 `npm run octoplanner -- workspace init`；按所选版本核对 Bun、Node 和依赖要求。

通过适配层把 ERP、MES 或 Excel 数据转换为 requirements、items、routings、resources JSON，检查稳定 ID 与引用关系，再加载规则并创建计划。情景调整沿 `plan load → plan revise --from-plan → plan diff` 的真实命令合同实施；Excel 回写用 `externalRef` 对齐原始行和基线，核对 diff 后按授权写入。

业务建模先确定变量、硬约束、优化目标和可行性判据。用人工可核对的小样本，再用真实样本检查资源冲突、工序顺序、停机、断料和不可行情形。每次读取命令返回的 `ok / data / warnings / notModeled`，解释未排程原因与未建模范围，并保存计划、差异和异常报告。排程结果经业务人员审核后，按批准规则写回系统或触发后续任务。

### 图纸：老马 drawings

站点页面标题为“老码识图”。公开前端列出 DWG、DXF、PDF、PNG、JPG/JPEG 输入，提供图纸库、解析、分类、参数检索和修订版本功能。使用前确认团队会话与权限，以目标账号核对支持格式和上传限制。

围绕实际业务要用到的参数设计识别任务，保留文件、图号、修订版和提取结果的对应关系。关键尺寸、单位、公差、材料等仅在项目需要且工具实际支持时接入；模糊、缺项、冲突或低可靠结果交人工复核。识别参数通过核对后，再验证报价、工艺或采购等后续业务动作的正确性。

### 选品：SKU Radar

SKU Radar 用于收集站点与商品变化信号，辅助爆品判断和选品。公开前端可见新商品、价格变化、促销页及图片/标题变化等监测项，以及站点、商品、报告和 URL 快照/差异入口。目标项目中先核对实际账号权限与支持范围。

Web 入口使用上表网址；公开前端给出的 CLI 入口为 `npm install -g skuradar-cli`，认证命令为 `skuradar-cli auth login` 与 `skuradar-cli auth whoami`。安装或运行前核对包来源、版本和当前命令帮助；本版未安装、登录或执行站点任务。

把业务目标转为筛选条件，记录目标站点/商品、时间窗和信号定义。用已知变化样本核对覆盖、误报/漏报、时间与来源，再由业务人员判断是否进入采购、试销或后续分析。页面操作、查询、导出和自动化接口分别核验，只把已验证的操作写进 Skill。

### 网站与系统接入

本版核验范围：OctoPlanner 已读取公开 README；老马 drawings 与 SKU Radar 已核对公开页面入口及前端能力线索。三个工具均未在本次手册编写中完成目标客户环境实测。

网站通过以上链接使用。登录权限、支持格式、导出方式及 API 可用性在目标项目中验证；入口 URL 本身不证明存在可调用的 API。已确认 API 时按其实际合同接入；采用网页或人工导出时，明确操作人、文件格式、保存位置和导入映射。涉及客户图纸或商品资料的上传，沿项目已有授权范围执行。

ERP 接入按实际 ERP 接口实施，分别核对网络、身份、数据口径和动作权限；直接写生产数据库按专项审核执行。每项专项接入均留下输入、调用或操作、产出、回读与失败处理证据。
