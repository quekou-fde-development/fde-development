## 2. 唯一真相源与命名

Design Token 是可复用的视觉规则，类似装修前约定好的材料、尺寸和色号。机器读取 `design/tokens.json`；人阅读本规范。调整数值必须先改 JSON，再生成预览。

| JSON 路径 | 意图与消费者 |
|---|---|
| `common` | 共享字体、字号、4pt 间距、描边、动效、层级、官方 `brand-*` 色 |
| `systems.bento / glass / ambient.structure` | 各风格的基础圆角、数字主次、玻璃透明度等签名 |
| `systems.<style>.colors.light / dark` | 完整的语义色彩，每个模式独立声明，禁止依赖另一个模式的颜色 |
| `systems.<style>.effects.light / dark` | 明暗模式对应的阴影、环境光和风险提醒前景 |
| `systems.<style>.density.comfortable / compact` | 页面与面板内距、模块间距、行高、控件高度、表格行距 |
| `parameterPolicy` / `systems.<style>.parameters` | 四个参数的统一范围、默认值和异常输入规则；每个风格显式引用 |
| `themes` | 仅保留未入选的阶段 1 参考版本，不属于本轮承诺的风格系统 |
| `gallery` | 风格实验室外框，使用独立的稳定配色，不参与客户调色 |

命名映射：`colors.light.surface.raised` → `--surface-raised` → `bg-surface-raised`；`fg.muted` → `--fg-muted` → `text-fg-muted`。状态的 `status.warning.fg` → `--status-warning`，`status.warning.bg` → `--status-warning-bg`。这种扁平 CSS 名称保留现有样品兼容性，JSON 中的分组表达语义。

解析顺序：共享基础 → 风格结构 → 实际明暗色板／效果 → 密度 → 圆角倍率 → 强调色相。参数不得改变业务状态含义、字体底线或布局签名。`surfaceMode=auto` 先根据系统偏好选择完整色板。

## 3. 颜色：品牌原色与界面角色分开

依据：用户提供《缺口公司VI系统.pdf》第 6 页，05 COLOR，v1.0 · 2026.07。前阶段已核对文字与页面渲染；文件路径与母本出处见 `design/references.md`。以下 HSL 与 VI 标准值等值；JSON 不存十六进制色值。

| 品牌 token | 色名 | HSL |
|---|---|---|
| `brand-ink` | 工业深墨 | 213.3333 / 72% / 9.8039% |
| `brand-blue` | 工艺蓝 | 220.3687 / 98.19% / 56.6667% |
| `brand-light-blue` | 桥接浅蓝 | 220.7812 / 100% / 74.902% |
| `brand-orange` | 现场橙 | 16.0396 / 100% / 60.3922% |
| `brand-steel` | 钢雾灰 | 211.5789 / 31.1475% / 88.0392% |
| `brand-cold-white` | 冷白 | 210 / 37.5% / 96.8627% |
| `brand-muted` | 说明蓝灰 | 211.0345 / 29.5918% / 38.4314% |
| `brand-paper` | 界面纯白衬底，非新增 VI 色 | 0 / 0% / 100% |

`client-blue / client-light-blue / client-action-text` 是受参数控制的界面衍生色。标准设置直接引用 VI 色；改变客户色相时只改变这些衍生色，永不覆盖 `brand-*`。深墨／白为主，蓝作强调，现场橙限于小范围风险提示；VI 的约 70% / 25% / 不超过 5% 是视觉方向，不按屏幕像素机械配比。

### 色彩组的意图

| 语义组 | 浅色方向 | 深色方向 | 具体用法 |
|---|---|---|---|
| `surface/base` | 冷白；Ambient 为纯白；Glass 的光晕受限 | 工业深墨 | 整个工作区背景 |
| `surface/raised` | 纯白 | 深墨 91%＋说明蓝灰 9% | 内容面板；Glass 在此基础上以 90% 不透明度合成 |
| `surface/overlay` | 钢雾灰 42%＋纯白 58% | 深墨 78%＋说明蓝灰 22% | 列头、次级区域、头像底 |
| `surface/hover` | 钢雾灰 58%＋纯白 42% | 深墨 65%＋说明蓝灰 35% | 表格行、次级按钮悬停 |
| `fg/primary` | 深墨 | 冷白 | 标题、业务正文 |
| `fg/muted` | 说明蓝灰；Glass 混入 20% 深墨 | 钢雾灰 | 次要说明，仍满足正文对比度 |
| `fg/subtle` | 说明蓝灰；Glass 混入 20% 深墨 | 钢雾灰 86%＋深墨 14% | 时间、编号、弱标签，不能靠降低透明度变灰 |
| `fg/inverse` | 纯白 | 深墨 | 反相表面；不能直接作为任意按钮的文字色 |
| `border/subtle` | 钢雾灰 60%＋纯白 | 说明蓝灰 60%＋深墨 | 行间和辅助分隔 |
| `border/default` | 钢雾灰 | 说明蓝灰 80%＋深墨 | 面板和控件边界 |
| `border/strong` | 说明蓝灰 58%＋钢雾灰 | 说明蓝灰 | 强分区；键盘焦点另用 focus/ring |
| `accent/default` | 加深的客户蓝 | 客户浅蓝 | 文本、链接、图表、选中状态 |
| `accent/solid` + `accent/fg` | 客户实色蓝＋纯白 | 同左 | 实心主按钮，必须成对使用 |
| `accent/soft` | 客户蓝 7%＋纯白 | 客户蓝 14%＋深墨 | 轻选中底，不表示业务成功或危险 |
| `accent/hover` | 实色蓝加深 | 同左 | 主按钮悬停，配 accent/fg |
| `chart/primary / secondary` | 加深蓝／说明蓝灰 | 浅蓝／钢雾灰 | 实际实线、计划虚线，同时保留文字图例 |
| `hero/bg / fg / muted` | 深墨／冷白／钢雾灰 | 同左 | Bento 主指标的固定深色表面 |
| `focus/ring` | 加深蓝 | 浅蓝 | 2px 键盘焦点环，与布局描边分开 |

`accent/default` 刻意不等于 `accent/solid`：标准工艺蓝配白字约 4.57:1，但直接放在冷白底作小字不足 4.5:1。因此浅色文字蓝混入 12% 深墨。客户色相调整还会按公式压低实色蓝的明度，保证白色按钮文字不低于 4.55:1 的生成目标；渲染后的实际对比度仍须验收。

### 状态色：与客户色相解耦的语义

| 状态 | 浅／深方案 | 非颜色标记 |
|---|---|---|
| success | 浅色说明蓝灰＋冷白；深色钢雾灰＋深色蓝灰底 | CheckCircle2＋“已完成” |
| warning | 两种模式均为现场橙底＋工业深墨字 | TriangleAlert＋“存在风险” |
| danger | 浅色 HSL(0 63% 39%) 字／(0 80% 97%) 底；深色 (0 82% 76%) 字／(0 32% 14%) 底 | 错误图标＋具体错误说明；禁止仅涂红 |
| info | 浅色加深客户蓝＋浅蓝底；深色客户浅蓝＋深蓝底 | Circle＋“正常推进”或说明文字 |

危险红是为严重错误／破坏操作保留的语义扩展，不冒充 VI 标准色。现场橙配白字不足 4.5:1，必须配深墨字。无底色的橙色提醒数字在浅色模式用深墨、深色模式用现场橙，不能直接复用橙底标签的前景。

## 4. 排版与数字

| token | 基础值 | 用途 |
|---|---:|---|
| `font-size-micro` | 11px | 编号、图例、辅助时间；不得用作主业务正文 |
| `font-size-caption` | 12px | 表格单元格、标签、辅助说明 |
| `font-size-body / label / section` | 13 / 14 / 16px | 正文／小节标题／面板重点 |
| `font-size-title / display` | 26 / 34px | 页面标题／比较器编号 |
| `font-size-kpi` | Bento 36、Glass 30、Ambient 26px | 指标数字；小屏可使用 title 档 |
| Bento `font-size-kpi-hero / hero-small` | 64 / 48px | 主指标；窄桌面及小屏用 48px |
| `line-body / tight / display` | 1.55 / 1.2 / 1.05 | 连续正文／标题／大数字 |
| `weight-regular / medium / semibold / bold` | 400 / 500 / 600 / 700 | 正文、控件、标题、品牌 |
| `tracking-normal / tight / label` | 0 / -0.035em / 0.1em | 正文／大数字与标题／短英文眉题 |

正文使用 Inter → 系统无衬线 → PingFang SC／Microsoft YaHei 后备。没有安装 Inter 时自然回退，不引入远程字体。数字字体栈为 ui-monospace → SFMono-Regular → Menlo → Monaco → Consolas → Liberation Mono → Noto Sans Mono CJK SC → monospace；所有数字启用 tabular-nums，金额右对齐。紧凑模式压缩留白与表格行距，保留字号底线，不把数据缩成难读小字。

## 5. 间距与密度

4px 为主布局基数。完整阶梯为 0、2、4、6、8、12、16、20、24、32、40、48、64px；2/6px 仅作图标、徽章和焦点偏移的细调。图表视口、侧栏宽度等采用具名尺寸 token，不把业务布局写成任意散落的尺寸。

| 项目 | comfortable 舒适 | compact 紧凑 |
|---|---:|---:|
| 页面内距 | 32px | 24px |
| 面板内距 | Bento 24px；Glass / Ambient 20px | 16px |
| 模块间距 | 16px | 12px |
| 表格行高下限 | 48px | 40px |
| 控件高度 | 36px | 32px |
| 单元格上下内距 | 4px | 2px |
| 表格行距 | 1.5 | 1.35 |

行高为下限，真实文字变长时允许行撑高。1280px 以下可按既有响应规则收缩外侧留白；手机页面内距 12px、模块间距 8px。表格与图表在自己的容器内滚动，禁止让整个页面横向溢出。Bento 的主次模块关系、Ambient 的“建议→项目”顺序不随密度改变。

## 6. 圆角、描边、层次与动效

| 风格 | 卡片／控件基础圆角 | 0.5× | 1× | 1.5× |
|---|---|---|---|---|
| Bento | 20 / 10px | 10 / 5px | 20 / 10px | 30 / 15px |
| Glass | 14 / 8px | 7 / 4px | 14 / 8px | 21 / 12px |
| Ambient | 10 / 7px | 5 / 3.5px | 10 / 7px | 15 / 10.5px |

描边固定 1px，焦点／强调边界 2px；圆角倍率不改变描边、pill、圆形头像和进度条端点。Bento 以尺寸差与深墨主卡表达主次，轻阴影只是补充；Glass 以 90% 不透明表面、24px 背景模糊、亮边和低透明度环境光建立层次（浅色两层光晕上限分别 4%／6%，深色为 24%／9%）；Ambient 普通内容不使用投影，AI 来源用局部蓝色渐变细边界标记。

阴影层级：none → raised（当前面板）→ floating（弹窗）。Bento 浅色面板为 0 2px 4px、深墨 3.5% 阴影，深色为同尺寸低透明黑影；Glass 浅色为 0 8px 32px、深墨 8%＋白色内亮边，深色为深墨 22%＋浅蓝 14% 内亮边；Ambient raised=none。弹窗采用 0 12px 36px，浅色深墨 16%、深色深墨 40%。完整值在 JSON effects 中。

层级 token：base 0、panel 1、sticky 30、popover 40、overlay 50、toast 60。原生 dialog 的顶层机制独立于 z-index，不能靠无限加大层级解决遮挡。

动效：fast 100ms、标准 160ms、slow 240ms；默认 easing 为 cubic-bezier(0.2, 0, 0, 1)，退出为 cubic-bezier(0.4, 0, 1, 1)。只用于 hover、焦点和必要的展开提示。系统启用减少动态效果时关闭过渡、动画和平滑滚动；不添加常驻闪烁、漂浮或渐变动画。

## 7. 四个客户参数与安全范围

这四项是可批准的定制范围，不代表可以随意改所有视觉值。

| 参数 | 推荐／安全范围 | 默认值 | 越界处理与代价 |
|---|---|---|---|
| `accentHue` | 推荐 215–230°；受支持范围 210–240°，整数步长 | `brand` = 220.3687°，保留 VI 精确原色 | 越界钳制；非数字回标准蓝；区间内取最近整数。越出蓝色家族会削弱缺口品牌，并需重新验证对比度，当前不开放 |
| `density` | comfortable / compact | Bento、Glass 为 comfortable；Ambient 为 compact | 未知值回该风格默认；不允许继续压缩字号与 40px 行高底线 |
| `radiusScale` | 0.5 / 1 / 1.5 | 1 | 非法值回 1；超过 1.5 容易使数据容器过圆、挤压边界；低于 0.5 会失去风格签名 |
| `surfaceMode` | light / dark / auto | Bento、Ambient 为 light；Glass 为 dark | 未知值回默认；auto 实时跟随系统，不支持偏好时浅色。禁止靠简单反色或降低文字透明度实现深色 |

色相仅改变客户强调色、相关图表和 AI 边界；不改变深墨／白的底色、橙色风险、红色危险、正文、布局与数字。色相和明度不是同一件事：为了保持白字可读，部分偏青的实色蓝会自动变深；深色模式的浅蓝文字也会按需提高明度，使其在最亮的悬停表面上达到至少 4.65:1 的生成目标。这些都属于受控衍生色。

参数预览写入 URL，可刷新复现；三种风格分别保留本次会话中的参数。重置“主题默认值”只恢复视觉参数；“重置样品”只恢复虚构业务数据。auto 模式在浅深切换时保留筛选、选中行和参数。页面未连接实际客户配置服务。

## 8. Do / Don't

### 共同规则

**Do**
1. 用 surface、fg、border、accent、status 等角色取色；新增用途先补 token。
2. 正文、辅助文字、输入值与占位提示均按至少 4.5:1 验收。
3. 标签同时写出状态并配对应图标，图表保留实线／虚线与图例。
4. 金额右对齐，数字启用 tabular-nums，编号使用统一数字字体栈。
5. 深浅模式分别声明完整的色彩组，不借用另一模式的前景。
6. 修改密度时一起调整控件、表格内距与行距，保留字号底线。
7. 焦点使用独立 2px focus/ring，键盘可到达每个操作。
8. 每次更改品牌值、透明度或参数范围后重新检查真实渲染。
9. 数据、布局和客户参数分别保存，切换主题不重置业务筛选。
10. 只把授权的视觉参数作为客户定制入口。

**Don't**
1. 不在组件中写字面量颜色类名、十六进制色值或内联样式。
2. 不直接用工艺蓝做冷白底小字，不用白字配现场橙底。
3. 不把“成功”变成客户强调色，也不让风险橙跟着色相旋钮变化。
4. 不用降低整个容器 opacity 的方式做次级文字或禁用态。
5. 不用缩小到 10px 以下来增加数据密度。
6. 不靠颜色、闪烁、hover 或图标单独传递关键业务含义。
7. 不把任意客户图片放在玻璃正文背后。
8. 不用无限加深阴影、增加 z-index 或放大圆角解决信息层级问题。
9. 不把演示摘要包装成真实 AI 判断，不自动替负责人作决策。
10. 不把视觉与组件验收当成真实业务上线验收；客户项目仍需确认数据、权限与保存结果。

### Bento · 模块拼图

**Do**
1. 让主指标与宽趋势图在桌面并排。
2. 主指标保持深墨表面与更大的数字。
3. 次指标采用较小数字，避免与主指标争夺注意力。
4. 通过模块尺寸和底色建立主次，轻阴影只作边缘补充。
5. 三个次指标与紧凑待办组成下一排。
6. 表格保持完整列头、筛选和状态文本。
7. 在手机上先主指标再趋势，然后次指标和明细。
8. 圆角变化仍保留不等大的模块关系。

**Don't**
1. 不退回四个等宽大指标作为唯一签名。
2. 不把每个指标都涂成深墨或工艺蓝。
3. 不把 64px 主数字用于所有数字。
4. 不用装饰图填补业务留白。
5. 不为了拼图造型拆散一个业务对象的字段。
6. 不把表格做成多个独立浮动卡片。
7. 不用大阴影代替模块主次。
8. 不因密度变化把项目表移到趋势之前。

### Glass · 玻璃层次

**Do**
1. 透明表面固定在受约束的深墨或浅灰背景上。
2. 面板不透明度保持 90%，blur 保持 24px。
3. 正文使用实色 fg token，不随玻璃透明度衰减。
4. 浅深模式使用独立的阴影、亮边与背景光强度。
5. 主动区分 panel、sticky、overlay 层级。
6. 渐变光晕只出现在背景，不盖住文字。
7. 不支持背景模糊时仍靠高不透明度与描边保留可读性。
8. 风险用小范围橙色标签和文字表达。

**Don't**
1. 不把透明度作为第五个客户旋钮。
2. 不把面板降低到完全透明或半透明白字。
3. 不在相同区域叠放多个高亮光晕。
4. 不在背景使用动态图、客户照片或视频。
5. 不让弹窗和下层表格混成同一视觉层。
6. 不把深色改为简单的白黑反转。
7. 不用荧光或光晕表达“已完成”。
8. 不让玻璃美感取代 hover、焦点和行分隔。

### Ambient · 内联智能

**Do**
1. 四项指标合成轻量概览条，使用分隔线而非四个浮动卡片。
2. AI 摘要放在项目操作区入口。
3. 摘要写明 AI 演示来源，保留“需负责人确认”。
4. 建议旁提供明确的风险筛选动作。
5. 项目表承担主要工作空间，趋势与待办作为辅助。
6. AI 边界只使用蓝系渐变，普通面板使用细描边。
7. 建议文本保持正文尺寸和对比度。
8. 在小屏仍按摘要、确认、操作、明细的顺序阅读。

**Don't**
1. 不把页面变成巨大的聊天窗口。
2. 不把 AI 摘要当成第五个 KPI。
3. 不给所有面板添加渐变边框。
4. 不隐藏人工确认标记来节省空间。
5. 不将建议按钮设计成默认已执行的状态。
6. 不让生成内容覆盖原始业务数据。
7. 不用脉冲动画暗示 AI 在实时推理。
8. 不退回 Bento 的深色大数字主卡结构。

## 11. 阶段 4：固定页面结构

新页面必须由配方 + 标准区块拼装，不得自创布局与颜色。正式配方固定为 Overview、List、Detail、Settings，完整顺序和接口见 `design/page-recipes.md`。配方顺序以用户原任务的阶段 4 要求为准：Overview 先四指标，再主次图表，最后活动流。Bento 在指标行保留主次大小与深色主卡，Glass 保留透明层次和受约束的环境光，Ambient 保留轻量指标条与内联摘要。原样品页继续保留已认可的 6 / 10 自由拼图差异，不改写正式配方顺序。

标准区块位于 `packages/ui/src/blocks`，四配方位于 `packages/ui/src/recipes`；`recipeCatalog` / `blockCatalog` 是固定目录。所有区块基于现有组件。新增内容宽度、设置导航宽度、趋势图尺寸、表格最小宽度使用 common 中的 recipe / settings token，从既有字号和间距阶梯推导，原品牌色与参数边界不变。

虚拟表格使用固定行高；多行内容放在详情页。阶段 4 的分页列表先全量筛选与排序，再切当前页，全选只针对当前页。Settings 的草稿与保存区分，危险操作必须明确确认。浏览器演示的数据与 AI 摘要均非真实公司数据或真实 AI 判断。验收记录见 `qa/phase-4-验收记录.md`。
