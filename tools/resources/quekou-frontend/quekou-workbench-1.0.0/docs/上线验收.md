# 什么时候可以让真实用户使用

工具包通过的是“前端设计与开发基础”的检查。每个客户的业务系统仍需以下真实场景验收。项目负责人负责业务结果；技术负责人负责数据和运行可靠性。人名由公司指定，本工具包不代为指定。

| 验收内容 | 谁负责 | 必须拿到的证据 |
|---|---|---|
| 对象、指标与状态口径 | 业务负责人 | 一份真实样本逐项对得上；未知值不显示成零 |
| 登录与权限 | 技术负责人 + 业务负责人 | 不同角色实际登录；直接调用服务也不能越权，不能只隐藏按钮 |
| 创建、修改与删除 | 技术负责人 | 保存后刷新、换账号/设备仍按权限可见；重复提交、失败重试、取消均验证 |
| 客户之间隔离 | 技术负责人 | 用两个客户账号尝试读取彼此数据，必须被拒绝 |
| 加载、空数据、失败、长文本 | 前端交付人 | 实际页面截图和可复现流程；手机及客户指定浏览器通过 |
| 记录与恢复 | 技术负责人 | 关键操作留痕、备份恢复演练、发布回滚方法 |
| 交付范围 | 项目负责人 | 数据来源、接入服务、剩余限制、用户培训与签收记录 |

危险操作按钮仅提供确认界面。服务端仍要核对权限、并发、幂等（同一次请求重试不会重复扣减或删除）和最终结果。
异步危险操作使用返回 Promise 的 onConfirm；组件等待完成，失败保留弹窗且允许重试。不要在回调中吞掉错误后声称成功。

组件包不提供登录、数据库、多租户后台、接口授权、审计服务或自动 AI 结论。预览页中的金额与 AI 摘要均为样本。
当前测试基准详见 RELEASE_AUDIT.md；未做完整辅助技术认证或正式客户负载测试。目标浏览器超出已测范围时，补测后再承诺。
