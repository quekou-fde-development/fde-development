# 调研输入与证据使用约定

## 加载链（上下游）

**上游**：`../SKILL.md §运行前提` — 接收通用调研输入、原始材料或补充回答时读取本文件。

**管辖文件（下游）：**
- `pre-review-analysis.md` — 证据可用后，从中形成业务流和系统架构理解。
- `clarification-and-decision-loop.md` — 证据缺失、冲突或只足以形成假设时继续读取。

**同级联动：**
- `nine-document-authoring.md` — 九份正文只使用此处界定的事实与决定。

## 输入包

随包 `../assets/通用调研输入文档.md` 保留通用输入的完整空白结构，便于在其他环境取得同一张调研表。每次运行指定该结构的项目副本；项目副本是本项目“该读什么、谁是权威、哪些材料尚缺”的入口，而非原始证据的替代品。部分填写、`《待填写》` 和不适用项是合法输入状态：已填部分用于分析，未知项进入问题簇，不适用项记录原因。它们只在影响最终设计时阻断九份文件。输入包应可定位到：

- 业务目标、交付范围、排除范围、成功或失败条件；
- 角色、岗位、客户或系统边界；
- 访谈转写、现场观察、跟票记录、真实样本、规则或合同；
- 既有系统、数据表、接口、文件交换或人工交接证据；
- 当前已确认事项、冲突、假设、缺件、可提问的人和验收要求。

读取时记录原件是否实际取得和阅读，以及它处于文档说明、源码核对、样例验证或目标环境实测中的哪一种状态。不能打开的路径、只有口头转述的能力、未读样本和未证实的接口都要保留为限制。

## Octopus 与 Arcubase 平台证据

本项目的候选架构固定采用 Workbench、Octopus 和 Arcubase。输入包应尽量收集下列平台事实；材料缺失时按影响进入问题簇或实施前核验，不能以案例配置补齐：

转写中出现的 “Occupace” 或 “AQBase” 统一按 Arcubase 归类；原始引文保留原词，并在引用处保留这一规范化说明。

- 目标是既有 Workbench 应用还是新应用；既有应用的目录、`package.json`、锁文件、认证 facade 和已选 feature 的实读证据；
- Arcubase App 的明确选择。既有 App 记录从官方列表或读取结果得到的精确 App ID、schema、表 ID 与稳定 field key；新 App 记录待批准的表、字段、`linkto` 关系和访问模型。名称相同或相似不能单独证明目标 App；
- 每个业务事实在 Arcubase 中的表、字段、Link、权威来源和持久化需求；日期、序列号、附件、公式、lookup、rollup 或批量写入的实际约束；
- 业务角色的来源、授权维护者、人员与 Arcubase 原生 organization actor 的映射证据、对象归属/负责人/审批人的业务记录，以及启用、调岗和撤权要求；
- 需要的 Host 能力与其当前类型或 `--help` 证据，包括 Octopus 目录、数字员工、会话或文件能力；Taskboard 仅在项目确有任务或项目工作流时列入；
- 真实人类会话、数据入口和撤权的允许/拒绝验证证据；项目涉及数字员工代办或 `conversation_member` 时，再收集发起/执行身份的验证证据。`conversation_member` 仍处于能力核验阶段，只能记录为待验证模式。

平台 ID、CLI 方法、SDK 方法、field type、`linkto` payload 与 access-rule payload 只在当前文件、当前已安装类型、官方 `--help` 或目标环境读回明确支持时写入。无法取得的细节标为缺件或实施前核验，不编造占位 ID、角色 ID 或方法名。

## 来源标记

每个会影响设计的陈述用下列其中一种来源状态：

| 状态 | 含义与处理 |
| --- | --- |
| `事实` | 可回到原始访谈、观察、样本、系统回读、规则或有权人明确陈述；附来源锚点。 |
| `已确认决定` | 有权人已选择的范围、规则或方案；附决定人、时间或记录位置。 |
| `推断` | 由材料推演的暂定关系；写出依据、适用条件与待确认点。 |
| `设计推导` | 基于已确认目标、流程和约束提出的字段、接口、页面、技术或实施方案；写出所依据的业务约束与设计理由，作为待审核设计而非客户事实。 |
| `冲突` | 两个可用来源给出不相容说法；保留双方，不自行裁决。 |
| `缺件` | 需要原件、样本、接口核验或回答才能继续判断；说明影响和负责人。 |

调研中取得的现场数字、阈值、频次、成本和容量只在原始材料明确支持时写入。模型不得生成这些值，也不得用案例项目的数值填空。

## 权威与冲突处理

同一主题优先采用本项目明确指定的权威源；没有指定时，将来源和冲突连同问题交给有权的人。访谈中的单次体验可以揭示异常、痛点或待验证假设，却不能自动成为所有角色、全部货主或所有时间段的通用规则。

指向外部文件、系统、规则、接口或工具的材料须闭合：取得并阅读其正文，或将其范围外化并写入缺件。仅有名称或一句功能描述时，不能把实际能力、字段或副作用写成事实；可以依据已确认用例提出候选接口、模型或自动化方案，并把能力核验保留为实施前提。

## 运行内工作材料

在 `working/` 中保存来源快照、事实与推断、流程段、问题和决定的对应关系。它们是候选九文档的可追溯依据，不另作为第十份交付文件。最终九份文档引用其稳定编号或原始来源位置，不复制大段转写。
