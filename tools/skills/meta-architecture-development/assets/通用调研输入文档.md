# 通用调研输入文档

## 如何填写

- 本文是 Meta Architecture Development 的输入：帮助 Skill 理解现状、目标和约束，提出方案并生成九份开发设计 Markdown。填写者提供业务依据；数据模型、页面与 API 由后续架构工作设计。
- 项目架构统一基于 Octopus、Arcubase 与 Workbench。填写实际业务和已有平台条件即可；Skill 负责把业务对象、权限和操作映射到平台能力。
- 已有访谈、流程说明或样本能够回答的问题，可以直接附材料并标明对应位置，由 Skill 提取。先填已知内容即可；空白和“未确认”会成为后续澄清线索。
- 先观察真实作业，再访谈；同一关键问题尽量记录不同角色的说法和差异。
- 用【观察】记录亲见事实，用【问】记录原话或转述，用【取样】记录获得的材料，用【测量】记录现场测得的数据。
- 事实、客户意向和未确认项分别填写；原调研手册中的方向性建议不能填为客户事实。
- 没有该场景或条件时写“**不适用：原因**”；未知时写“**未确认：待向谁或取什么材料确认**”。
- 拍照、录屏、导出和带走样本前，先记录许可范围；样本可脱敏后附路径或链接。
