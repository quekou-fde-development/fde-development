# 交接与合并规则（jh 套件判据源）

本文是 `fixtures/assertions_jh.json` 里各条 `source_anchor` 指向的判据出处。
断言不能自证——每条断言的规则必须能指回一份人写的规则文，否则「按什么判」
这一问就没有答案。

## 交接与合并规则

### 交接（handoff）

费率单由财务在流程外整理，交接回来时须同时给三样东西，缺一即拒收：

1. **交接物本体**（`h0_payload.csv`）——原样落盘，不在接收侧改写。
2. **内容哈希**（`payload_sha256`）——sha256 前 16 位。落盘后实算一次与账本
   记录比对；不等即交接物在途被改，本段不得放行。
3. **接收回执**（`source_id` / `received_at` / `receiver`）——三字段均须非空。
   出问题要能找到具体的人和具体的时刻，只记「已收到」不构成回执。

接回的行须含 `id` 与 `sku` 两个必填字段。行数对得上不代表字段齐，逐行验。

**源可机械重读性**：`human_handoff`。交接物由人在流程外整理，本流程内无从
机械重读其上游，故本段 T2 恒为 `UNVERIFIED`，不得改判 PASS。

### 合并（join）

按 `sku` 把接回的费率单与内部费率表合并：

1. **左集全覆盖**——左表（接回的行）每个 `id` 要么出现在 `joined` 里，要么
   出现在 `unmatched_ids` 里。两处都没有 = 单子被静默吞掉。
2. **一对一**——`joined` 里同一 `id` 不得出现两次。右表重键会把左行放大成
   多行，金额随之虚增，这是 join 最常见的错法。
3. **未匹配记名单**——`unmatched_ids` 记具体单号，不是只记 `unmatched_count`。
   数对得上而查不出是谁，等于没登记。

内部费率表故意不覆盖全部 sku（`30044` 缺）：未匹配是常态而非异常，规则要求
的是把它登记下来，不是假装它不存在。
