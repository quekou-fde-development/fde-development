# meta-orchestrator 设计规格

> 本文记录 orchestrator 的设计规格，作为「用 meta-skill 蒸 orchestrator」的输入语料。设计决策已收敛。这是**描述性**规格（给 meta-skill 读的素材）；命令式的执行要求，是 meta-skill 蒸出的 SKILL.md 的事，不在本文。

---

# 第一部分 · 定位与原理

## §1 定位

**同一棵分形树，两档分辨率的物镜。** 系统的全部工作流是一棵分形树状结构（判断段与执行段沿时序交替复合而成，详 §2）。meta-orchestrator 与 meta-skill 不是「编网 vs 编点」两种对象的编译器——逻辑上**没有「点」这个对象**（详 §2）——它们是切同一棵树的两档物镜，差别只在观察分辨率：

- **meta-orchestrator** = **第一层分辨率**的编译器，也是 orchestrator 的编译期实体：把整棵分形树画出来，沿 time sequence 的跨命交接处把树切成段、焊上段间的边，编完**退场**。
- **meta-skill** = **第二层分辨率**的编译器：在每一条段**内部**切出「执行段 ↔ 判断段」、把执行段写死成确定动作，产出这条段的一份 SKILL.md（内部四环链目的 / 标准 / 指标 / 路由自洽）。

**运行期零 orchestrator 实体。** 那只「无形大手」的意志被烧进各 skill 的触发结构里，运行期不以一个实体在场调度——系统靠各 skill 被各自的触发器唤起、自主协同跑出来。orchestrator 编译期留下的唯一可见痕迹 = 一份拓扑清单（§5）：运行期不出现，但有迹可循。

## §2 结构模型（第一性原理 · 全部下游条款的推导基座）

本节的概念是全文地基。下游每一条流程规则都从这里推出，故先立此。

**任何工作流的生成结构 = 一棵树状分形 + 挂在局部的 loop 环路。** 一切具体系统只是这棵树在某个分辨率、某个切片上的呈现。

**唯二元件：判断段与执行段，沿时序交替复合成链。** 逻辑上没有第三种元件，也没有「点」——一个 skill / 一个「节点」看似是点，其实是一条**段**（内部是「执行段 + 判断段 + 执行段…」的复合链，看着像点、实为一条链）。

- **执行段** = 一段确定动作序列，本身无裁决。
- **判断段** = 有内部体积的裁决工作，产出一个裁决值，用它驱动**三种行为之一**（穷尽，无其他可能）：
  - **放行** —— 本步足够 → 推进到下一段；
  - **loop** —— 本步不足 → 回到上一轮、同段再跑一遍；
  - **分流** —— 判断分叉 → 走多条互斥下游里的一条。
  - （段尾「自检 out(S) 达标否」就是一个判断段：达标 = 放行、不达标 = loop。）
- 树**递归嵌套**：任一执行段调高观察分辨率，内部都能再展开出「执行段 ↔ 判断段」的交替；反之任一「执行接执行」，调低分辨率就并成一个执行段。所以「判断段 / 执行段」不是两类互斥的对象，是同一条链在某分辨率下的两种角色——这也是为什么不能把「判断段 = 分叉点、执行段 = 分支」对立起来（分支自己就能含判断段）。

**局部 loop**：两种回绕挂在树的局部，都不改变整体树状骨架——**段内 loop**（判断段裁「本步不足」、同段重做）与**回边**（判断段裁「打回」、放行另一段的下游、跨段退回）。（两者的精确区分在 §7 第 3 步给操作判据。）

**实际系统 = 这棵全树的任意局部片段。** 单个执行段是合法片段；一个判断段 + N 条分支是合法片段；共同祖先（如「人的调度」）落在系统边界外、于是系统呈现为多个互不相连的无根独立段，也是合法片段。**片段的形状不构成独立类别**——它们都是同一结构的局部呈现，用同一套规则处理。

**段与边的本体（测度视角）：**
- **段** = 有测度的区间：内部有执行体积。判断段与执行段地位平等，一块是不是独立的段，资格只看它尾部有没有独立的「自检 → 落 stamp → 放行下游」检查点（操作判据见 §7 第 1 步）。
- **边 = 测度趋零的退化判断段**：当一个判断段简单到无需内部建模（「上游 stamp 在不在？在 → 放行下游」），裁决塌缩、内部体积趋零，于是这条段退化成一条**边**。边不是独立于判断段的新对象，是判断段的极限形态——这正是「逻辑上没有点」的来处：看似连接两段的「点 / 线」，其实是退化到零测度的判断段。
- **汇合（join）= 退化的合取判断**（「两个 stamp 都在吗？」）：编码上落为下游触发器的合取条件，不单独成段。
- 上游段落下 stamp 与下游段的触发器变为可触发，是**同一个零测度交接的两种写法**（这是边契约由上下游双端声明同一实体的依据）。

> **术语澄清 · 图论节点 ≠ 本体论零测度点**：本节说「逻辑上没有点」，否定的是「无内部体积的零测度点」。下游 §8 的「节点规格包」「网络节点模式」里的「节点」是另一层意思——**图论顶点**（graph node）：一条段作为网络这张图上的一个顶点时的角色名，它指的恰恰是一条**有内部结构的段**，不是零测度点。两词分属图论层（顶点 = 段）与本体论层（段不塌缩成点），不冲突、勿混。

**切段 = 选定观察分辨率，不是发现客观唯一边界。** 同一系统在不同分辨率下的切分都是合法投影。选哪个分辨率，判据是**治理需求**——哪里需要独立的 stamp / 独立的存活兜底 / 独立的完成核验，就在哪个粒度切开。逻辑等价时能少则少（§5 边计数软准则）；治理需求不明处**默认不切**，标 `resolution_pending` 留人核，既不臆造也不静默丢。（「治理需求」是全文的第一切段判据，下游多处引用本定义。）

**分辨率级联（工具分工的本质）：** 同一根光轴、由粗到细的两档物镜——**第一层 orchestrator**（画整树、沿跨命交接切段焊边）→ **第二层 meta-skill**（段内切出「执行段 ↔ 判断段」、执行段写死确定动作）。**每层在自己的分辨率上把判断密度就地吸干，往下移交的自由度递减**——到执行端全是写死的机械动作，弱模型也能跑。（meta-skill 在段内还能再下钻更细的分辨率去处理单个判断段，那是 meta-skill 的内部事，不在 orchestrator 这层承重。）

**命内交接 vs 跨命交接（三种排除的本体论根据）：** 交接有两种性质——**命内交接**（同步 call-return / 段内 loop / re-invocation）是零等待的逻辑交接，控制权不出门；**跨命交接**（边）可隔任意墙钟时间、可合取数轴外的信号（cron / 人）。二者的区别就是 §7 第 1 步「三种排除」的根据：三种排除是**分辨率边界守卫**，阻止高分辨率（段内）结构泄漏到低分辨率（网络）层。

## §3 存在理由（判别先于编织）

**不预设所有工作都是系统，先判别。** 判据是**一条连续的命能不能把整个工作流线性盖住**：

- **能盖住** —— 时序连续、一条命持续不断走到底 → **单一线性流**，**不需要 orchestrator**，直接交 meta-skill 编出一条段（一个 skill）就够。
- **盖不住** —— **跨时间尺度流**，**需要 orchestrator** 用多条段编织。「盖不住」有两种、都算（这是一个**四维拓扑**：时间轴上的先后与并行都在）：
  - **持续离散** —— 时序断开，被多个场合各自启动（跨小时 / 日 / 周 / 月 / 季，横跨多资源域与执行主体），如 daily→dream 隔夜交接；
  - **持续重合** —— 时序重叠，多条命同时并行推进、需要协调汇合，如同一时窗内两段并行到一个汇合点。

**「编织」的本质 = 多条段之间互相编织。** 每一条连续段各自是一个 skill（由 meta-skill 编），orchestrator 干的是把这些段**之间**的时序关系（先后续接 + 并行汇合）织成一棵树。

**为什么单 skill 织不了这棵树**：meta-skill 编出的单条段只描述「一条命内怎么干」，它四环链的四个槽全部朝内，**没有一个槽叫「邻居」**。跑 N 次 meta-skill 得到 N 条内部自洽的段，但段**之间**的时序、移交、分工——「多条命之间怎么接力、谁先谁后、哪些并行、各管哪块」——一条都不会自动长出来，因为这些信息不属于任何单条段，悬在段与段之上。

**所以 orchestrator 的第一职能是判别，第二职能才是编织**：判出单一线性就交 meta-skill、自己退场；判出跨尺度（离散或重合）才进编织。这与任何具体系统、任何具体故障无关。

# 第二部分 · 契约

## §4 输入契约

**吃**：一份 / 多份描述**某系统整体运转逻辑**的原始语料——节律、状态流转、工作流与信息流的走向及交汇点。**形式不限**（agent 文件 / 流程描述 / 运营手册 / 访谈转写皆可），只要它定义的是「一个系统怎么运转」。（记忆系统这例恰好是两份 agent 文件，那是样本的偶然形式，非输入的本质要求。）

**不吃案例**：案例在下游 meta-skill 编单条段时才进场。分层 = orchestrator 管树的骨架，meta-skill 管段的血肉，案例是血肉的原料。

**指针闭包**：语料常以**指针**引用外部命名运转单元（「调用 X skill」「走 Y 流程」）而不定义其内部运转。遇此二选一：
1. 把该单元的文档（SKILL.md / 流程文件）追齐进 `00_input/`，按正常流程编；
2. 显式声明该单元 out-of-scope + 理由，该单元不入网、在 `topology.json` 的 `resolution_pending[]` 登记（位置 + 待附文档）。

- **薄料硬编非法**：仅凭指针级提及（一个调用点 + 一句功能描述）为整段编出 SKILL.md = 臆造（血肉只能来自模型先验、不来自语料）。
- **inferred 补足只管字段级缺口**（段已有料、个别 stamp 字段 / schema 细节缺），**不管整段无料**——整段内运转缺失 = 标 `resolution_pending`，或出「此段缺料」诊断（合法输出的第 2 种），不得硬编。
- 渐进式披露架构下，指针密度语料是常态而非病，指针闭包即其配套输入规则。

**两个工作模式：**
- **从零编网**：只有系统运转语料，从头切分、编织、生成全套 skill 网络。遇语料没写死的细节（某 stamp 的确切字段、某边启动数据的精确 schema），不得停摆、也不得静默编死——按合理默认补一个 schema，标 `inferred` + 一句依据，留真部署时人核。
- **复审已有网**：系统已有在跑的 skill 网络。此处有一道**强制隔离**——现役 skill 网是「已被蒸馏压缩的成品」，主 agent 直接读它会被现状实现语义污染（先入为主把「现状」当「应然」，delta 就照不出来了）。故：
  - **必须派 sub-agent** 把现役 skill 网当一份特殊语料读入，**还原**成它所表达的原始流程网（现状的应然投影，即「这套 skill 实际在跑的是什么流程」）；
  - 主 agent **只接收 sub-agent 还原出的流程网 + 原始运转语料（实然）**，据此**独立**推出「应然网」，再与现网实然逐条对比；
  - 主 agent 全程**不直接接触现役 SKILL.md 正文**，把现状实现的语义污染隔离在 sub-agent 那一侧。
  - 复审**不另开分支**（判别 → 梳理 → 切分与从零编网同一条流程）。**强制产出 `03a_as_is_vs_should_be.md`**（现网边 / 应然边 / delta / 修复落点）：复审的交付是这份 diff，不是另画一张理想拓扑；无 diff = 复审退化成重画理想网。inferred 细节以现网实然覆盖（现网怎么写就怎么定）。
- **复审 surface 出「应然该有、现网没有」的段**（如某段现网嵌在别的 skill 载荷里、无专属段）：这类段走**从零建**（无可审的现役本体），并在 03a 里标注「现网嵌入位置 + 应剥离成独立段」作为 delta；规格包的「现役 SKILL.md 文本」字段对这类段留空 + 注明「无现役对应，从零建」。

**两种合法输出：**
1. 一张**网络拓扑清单**（§5）+ 据此调 meta-skill 编出 / 加固的 skill 网络；
2. 一份**诊断**：哪条边在语料里悬空、需人补。

## §5 输出契约 · topology.json

**网络拓扑清单是「看不见的 orchestrator」的落脚点**——运行期它无实体调度，但它编出的树得有迹可循。

- **单一权威 = `topology.json`（机器可校验）**；`topology.md` = 从 json 渲染的人读视图，**不手写第二套边定义、不反向覆盖 json**（避免双权威）。脚本只认 `topology.json`。

**topology.json 内容 schema**（顶层盖一个 `topology_version` = 编译起始分配的 run-id，防漂移机制见 §9）：

- **⓪ verdict**（顶层必填，二值）：`single_linear` / `cross_scale_network`。「编几条段」由段数说话、「织不织」由边数说话——**verdict 不重复编码图结构已有的信息**（单一权威）。多分量零边的退化网络 = `cross_scale_network` + N 段 + `edges: []`，是合法产出。
- **① 段清单**：每 skill 一段 + 触发方式 + **外部支脚标记** + 触发前置 stamp + 资源域 × 主体。
- **② 边清单**：每条边 =
  - `edge_contract_id`（边契约版本 ID，非永久边名，内容任一变即换新 id）+ `edge_contract_hash`（契约内容指纹）+ 上游段 → 下游段 + 启动数据 schema + 触发器配置 + 上游段尾审计的失败回流；
  - `kind`（闭合枚举 `{normal, survival_backstop, back_edge, report_probe}`）；
  - **survival_backstop 边必填** `watcher` / `watched` / `probe_type`(`exact`|`superset`) + 扫描的 stamp + 「驱动而不代写」标记；
  - **report_probe 边必填** `watcher` / `watched` + 报告落点，无驱动字段；
  - 回边 / 环照常登记，与普通边同形；
  - 同 tick 定序不设独立 kind，以段 / 边的 `same_tick_order` 字段承载。
- **序列化硬契约（机读形状三条写死，防「语义对、形态散」的机械 FAIL）**：① 一切 stamp 类字段值 = **字符串数组**（单个也写 `["x"]`，禁裸字符串 / 对象嵌套）；② 每条边必有 `from` / `to` 两端段 id 字段（backstop 的 `watcher` / `watched` 是附加语义字段，不替代 from-to 方向声明）；③ 边标识符键名**统一 `edge_contract_id`**，禁 `id` / `edge_id` 等别名双轨。完整字段形状的单一权威源 = 蒸馏包 `references/topology_schema.md`，`check_topology_version.py` 按其解析——形状漂移 = 机械层直接 FAIL，不留给判卷人识别。
- **③ 复用依赖清单**：某段被另一段同步 call-return 调用，不是边但改动会波及 → 登记「X 复用 Y」，否则这条依赖在拓扑里不可见、Y 改了波及 X 而审计照不出。
- **④ 时序表**：能机械回答「任意时刻该醒哪些段、按什么序」，含同一 tick 多段触发时的定序。
- **⑤ liveness_gaps[]**：含外部支脚、但网内无独立节律下游可兜底的段 → 段 id + 免配原因 + 部署期补配提示。
- **⑥ resolution_pending[]**：治理需求不明、按「默认不切」处理的交接，及指针闭包 out-of-scope 单元 → 位置 + 待定原因，留人核。

**退场态最小 schema**：verdict = `single_linear` 时 orchestrator 第 1 步即退场，仍须落一份 topology.json：必含 `verdict` + 段清单（1 段：触发方式 + 资源域 × 主体）+ 空边清单 `edges: []` + 移交指令。退场不等于不产拓扑——判别结论本身要可机读、可审计。（多分量零边不是退场态：照走网络流程至伪边剔除完成，产 N 段 0 边的完整 topology.json。）

**边计数软准则**：不钉死「边最小计数单位」。存活兜底边、并行段入边等是否显式单列成多条边，属**粒度自由度**——只要各自 topology 校验都过（边集闭合 + 两端声明一致）即皆自洽合法。准则：**逻辑等价时优先更少的边 / skill**（能合则合；多条亦可，只要每条逻辑独立成立）。

**生命周期 = 静态产物 + 受控更新**：orchestrator 编译时生成，平时**冻结当基准**，不被日常运行偷偷改脏；**只有再次跑 orchestrator**（复审 / 加新 skill）时才由 orchestrator 重写它、升 `topology_version`。它永远是「orchestrator 最后一次编译的快照」。

**落点**：放 Meta Zone（横跨工作库 / 记忆池两域，谁都不该独占，归自指域）。作为 reference 文件落盘，运行期不读入，审计 / 复审时才读。

# 第三部分 · 核心流程

## §6 workspace 与主体划分

**orchestrator 是长链**，单 agent 从头扛到尾则上下文滚雪球（前面步骤的草稿 / 弃案堆在 context，越往后越脏）。**故第一个动作 = create workspace，此后每步产物落盘，下一步只读上一步落盘的成品。**

**增益（不止省 token）：**
- **输入变干净**：第 N 步只读 N-1 步落盘成品，读不到前面的推理垃圾，信噪比高。
- **可审计**：每步 checkpoint，错可定位、可单步回炉，不整条重来。
- **天然适配**：第 4 步「每段逐个外包 meta-skill」本就该是「每段一子 workspace、落盘一份 SKILL.md」。

**workspace 布局：**
```
orchestrator_ws/<系统名>/
├── 00_input/            原始语料 +（复审模式）现役 skill 网络快照
├── 01_flow.md           第0步：标了三类要素的完整时序流程图 + 网络尺度目标函数 + 语料事实清单
├── 02_verdict_cut.md    第1步：判别结论（single_linear / cross_scale_network）+ 切出的段 S 结构
├── 03_nodes_edges.md    第2步：段属性 + 外部支脚标记 + 边清单
├── 03a_as_is_vs_should_be.md  （仅复审模式）现网边 / 应然边 / delta / 修复落点
├── 04_nodes_edges.md    第3步：尾审计配置 + 段内 loop + 边触发器 + 存活兜底边 + edge_contract_id/hash + topology_version
├── 05_skills/           第4步：每段一子目录，各落一份 meta-skill 蒸出的 SKILL.md + _spec_in.md
├── 06_check.md          第5步：网络级六检报告
├── topology.json        最终产物：网络拓扑清单（机读单一权威）
└── topology.md          最终产物：网络拓扑清单（人读视图，从 json 渲染）
```

**哪些步拆 sub-agent —— 判准是「干净输入 vs 连贯语境」，不是「避免自指 / 提质量」。**

> 「换 sub-agent 就不自指、质量变高」不成立——它把工程 / 上下文卫生问题误诊成执行体本质缺陷。真实因果大概率是「sub-agent 输入更干净」，则解药是**落盘 + 干净输入**（工程层），不是**换主体**（执行体层）。

**自指在不同环节性质相反：**
- **检验**环节，自指是坏事（自己测自己有盲区）→ 拆 sub-agent 是解药（同 meta-skill「编译者不自测」总则）。
- **编译 / 推导**环节，自指是必须的——步与步强推理依赖，需同一个脑子持前因推后果。硬切给互不相识的 sub-agent（只读落盘、丢推导语境）会在步间接缝掉链子：sub-agent 读落盘 = 默认信任落盘是对的、不回头质疑上游，于是上游的错误结构被原样继承、无人叫停。

**划线：**

| 步 | 主体 | 理由 |
|---|---|---|
| 第 0–3 步（画图 → 判别切段 → 标属性识外部支脚 → 焊边配尾审计） | **主 agent 连贯做** | 一条强推理依赖链，需持前因推后果、随时质疑上游 |
| 第 4 步（每段逐个外包编段） | **拆 sub-agent** | 段彼此独立、可并行；每段外包给 meta-skill（它内部自带 sub-agent 机制），输入是干净的节点规格包 |
| 第 5 步检验部分（六检的 ③ 语义闸 / ⑤ dogfooding / ⑥ 覆盖闭合） | **拆独立 sub-agent** | 检验类，需编译者供不出的独立证伪源；覆盖闭合尤须独立——静默丢块正是编译者自己的盲区 |
| **段尾审计**（运行期机制） | **段内强制调独立 sub-agent** | 生产者不自审；只读落盘、与主对话隔开 |
| **复审模式还原现役网**（§4） | **强制派 sub-agent** | 现役 SKILL.md 是压缩成品，主 agent 直读会被现状语义污染 → sub-agent 隔离还原，主 agent 只拿还原结果 |

> **隔离总则**：凡「独立证伪 / 去污染 / 防自审盲区」的环节，一律强制派 sub-agent，且在 workspace 产物里显式标注该步的独立性来源——不接受 inline 自审冒充独立背书（见下「降级路径」）。

**无 sub-agent 派发工具时的降级路径**：执行环境未暴露 Agent / Task 派发工具（如某些 workflow 嵌套环境）时，第 4 步编段、第 5 步检验的 ③⑤⑥、段尾审计**字面不可派独立 sub-agent**。此时**不得静默 inline 自审冒充独立背书**，须：
1. 主 agent inline 完成，但在 `06_check` 显式标注「独立性未达（无派发工具）」，不记「独立背书」；
2. 机械层（六检的 ①②④ + M6 闸）不受影响，照常客观背书；
3. 把「③⑤⑥ 独立盲跑」作为一条**遗留验收项**移交——由具备 Agent 工具的环境（主会话直接派 / 换环境）补一轮独立盲跑再升背书。
- **编排层正解**：把 ③⑤⑥ 独立检验提为**编排器上一层的独立阶段**（如 workflow 里一个独立 agent 调用，clean context 只读编网产物盲跑），绕开「嵌套 agent 不能再 spawn」的结构限制。

**「质量是否真变高」怎么验**：不靠推测，靠 meta-skill 第 9 步 Improve 的双盲 comparator + 胜负账——「全主 agent 跑 vs workspace 分步落盘跑」同任务双盲对比，让账说话。

## §7 五步流程

**层次铁律**：**先画完整时序流程图（纯描述）→ 图上标三类要素 → 判别与切段是读图副产品 → 后标属性焊边。** 判别不是独立前置步骤：图**连通且零断点** = 单一线性，其余（有断点、或多分量）= 网络，看图即得。触发器 / 资源域是段成型**之后**才标的属性，不能当起点。判据是「看图数断点」而非「凭空判整体属哪类」——地基从画出来的图得，故稳。

### 第 0 步 · 画完整时序流程图（第一动作 · 纯描述，不判不切）

本步先就地钉死三个画图要素术语（下游各步都用）：
- **持续断点** = 控制权交给「钟 / 人 / 外部过程」等待、由更晚的进入点拾起的口子。
- **判断分叉** = 某个判断段的产出是裁决、走两条下游里的**一条**（if / else，互斥）。
- **同时并行分叉** = 一处劈成两条**同时推进**的下游线（非互斥，两条都走）。它是一等要素，画图阶段即标出——与判断分叉区分标注，是同 tick 定序的前提；混为一谈 = 同 tick 并发排不出序。

**读**：`00_input/` 原始语料。

**输入体裁分支**：语料是**规则表 / taxonomy**（按对象或职能组织，如 agent 规则文件）而非时序叙事时，先做前置归置——从规则中提取「什么时刻 / 什么条件下发生什么」的时序事实，铺成时序骨架再画图；归置结果整体标 `inferred`（逆推带推断）。复审模式下以现网 skill 的实际触发结构校准归置偏差，分歧处以现网实然为准记入 03a。语料本身是时序叙事 → 跳过本分支直接画。

**做**：从系统启动处出发，**纯按时序往后推**，把「系统在做什么、再做什么、遇判断往哪走、哪里并行」铺成一张连续的流程图。**只描述、不切段、不判别、不碰触发器。**
- **画图分辨率规定**：图画到「判断段 ↔ 执行段」交替的粒度即止，**不下钻**到判断段内部（那是 meta-skill 之后的分辨率，orchestrator 画到那层 = 越级抢下游的活，图必脏）。执行块在本图上是一个块，不展开内部步骤。
- **显式标注三类要素**（持续断点 / 判断分叉 / 同时并行分叉），缺一即图不合格、回本步。
- 把每条路径的时序展开充分：某块紧接谁、产物流向谁，沿时序钉死位置。梳理到位时「某块归哪段」自动落定，无需另设归属判准。
- **语料事实清单**（第 5 步检 ⑥ 的账本）：画图同时抽取一份运转事实清单——语料中每个「命名运转单元 / 时序事件 / 监视关系」一行（id + 语料出处句）。清单是**抽取**不是设计：只登记语料说了什么，不判归属。此后每步处置一个事实必销账，检 ⑥ 凭此清单验零无主事实。

**写**：`01_flow.md`（标了三类要素的完整时序流程图 + 网络尺度目标函数一句话 + 语料事实清单）。

### 第 1 步 · 读图判别 + 切段（判别与切段都是读图副产品）

本步先就地钉死段与边的操作术语（§2 已给本体定义，这里给「怎么识别」的操作判据）：
- **执行段 S** = 一口气跑到自检、留下一个独立完成检查点的一块。**段边界 = 有独立「自检 → 落 stamp → 放行某下游触发器」检查点处。**（不用「控制权连续不交出」定义——同一次执行内也可切两段，只要中间有独立自检-stamp 检查点。）
- **out(S)** = 段 S 的产出；**stamp** = out(S) 经段尾审计达标后落下的完成标记。
- **授权断点** = 下游触发器含「等一个人的 C 级 verdict」的边。它合法：人在此做的是**授权**（裁决要不要做），不是运行期**编排**（决定怎么接线）——边走向仍是 verdict 值的确定函数（准 → 下游写入段跑；否 → 终止或回流），与「零软边」不冲突。其下游写入段独立成段。

**读**：`01_flow.md`。

**判别（读图即得，二值）**：图上有无跨命交接要焊——
- **图连通且零持续断点**（一条命走到底）→ **`single_linear`** → 整条交 meta-skill 编**一个** skill，orchestrator 退场，`02_verdict_cut.md` 写判别结论 + 移交指令，结束（仍产退场态最小 topology.json，见 §5）。
- **其余**（有持续断点，**或图不连通**）→ **`cross_scale_network`** → 进网络流程（切段 → 标属性抽边 → 焊边）。**连通性是判别的一部分**：零断点但多分量（N 个互不相连的独立根段，如两个动作各自被人触发、互不启动）不是单一线性——它是网络的**退化片段**（§2：全树的无根局部呈现），照走网络流程，跑完伪边剔除后自然产出 N 段 0 边的合法拓扑，交 meta-skill 编 N 个独立 skill。
- **零断点图如何过图闸**：单一线性图上三类要素可以全为 0——图闸只要求「每类要素**有没有被显式排查并标注**」，不要求「每类都 ≥1」。全 0 但每类都写了「核查：无一处 + 依据」= 图合格；漏标某类未核查 = 不合格回画。

**切段判据 = 治理需求（第一判据，§2 定义）**：切段 = 选定分辨率，在哪切由**该处是否需要独立治理**定——需独立 stamp / 独立存活兜底 / 独立完成核验**任一** → 在此切开（即段颗粒度下界）。
- **叙事钩子是治理需求的语料证据**（非独立判据）：下游被描述为独立启动的命名运行单元（「Y starts / runs after X」）、或有显式 stamp 交接叙事 → 治理需求证据成立、切；同一执行体内动作接续（「then consumes / uses …」）→ 无证据、不切。
- **治理需求不明处默认不切**（能少则少），但必须在 topology.json 标 `resolution_pending`（段 id + 待定原因）留人核——不臆造、不静默。切完由边计数软准则收敛可合并处。

**切段操作（沿断点切，读图副产品）**：两个相邻特殊标记（断点 / 分叉）之间的连续截 = 一段 S。
- **三种排除不切**（判据 = 有无「放行新下游」的独立 stamp 检查点，§2 命内交接）：
  1. **re-invocation**——整段被同类外部事件重新拉起 = 同一段 N 次执行，每次跑到尾落 stamp，但没放行「另一个」下游段，不是 N 段；
  2. **同步 call-return**——A 调 B、B 返回 A 续跑，B 是段内工具、不落「放行下游」的 stamp；
  3. **段内迭代 / 循环**——循环不在迭代间放行下一段，归第 4 步 meta-skill 管。
- **同时并行分叉的两条线 = 两段并行段**（都要走），不是二选一；它们若在更晚处汇合，汇合处按断点处理。
- **授权断点照常切 + 出口闭合**：两侧照常两段，下游写入段（如毕业 / 季度归档类）独立成段，不并入上游。**verdict 每个出口分支必须有归宿**——「准」支必须接一条正式执行段（写入段入网、有边），或显式 out-of-scope + `resolution_pending`（语料确实没写 verdict 后做什么）；「否」支同理（终止 / 回流，显式写出）。授权断点存在而准支既无下游边也无 pending 标注 = verdict 悬空（人裁完无段接住，裁决静默丢）= 标红，不得带病进第 2 步。
- **同执行体多段实例化判据**：同一执行体在一次唤起内承载多个节律的载荷（如周日夜 dream = 日级代谢 + 周级载荷）时，段身份从治理需求推、不从执行体推——各节律有独立 stamp / 独立兜底 / 独立核验需求**任一** → 各自成段实例（普通边相连，模式 = 同执行体立刻，`same_tick_order` 定序）；载荷无独立治理需求（无独立 stamp、失败随宿主段一起 bounce）→ 并入宿主段作内部分支、归 meta-skill。两可时从「默认不切 + 标 resolution_pending」。
- **根节律终止**：切段沿「上游 stamp 放行下游」链条前推，终止于**根触发器**——无任何上游 stamp、纯由外部支脚（人开机 / 到场、物理 cron、人的动作）唤起的段即根，链在此封顶不再上溯（防止无限上推找「谁触发了人开机」）。

**写**：`02_verdict_cut.md`（判别结论 + 切出的段 S 结构，每段标起止特殊标记；注明哪些「重启」属三种排除之一已剔除）。

### 第 2 步 · 标属性 + 抽边 + 识别外部支脚（段成型才有附着对象）

本步先就地钉死触发相关术语：
- **触发器 trigger** = cron 时刻 / 状态条件 / 人的动作 / 上游 stamp 就位。**可并置**（多个条件合取）。
- **外部支脚** = 触发器里非 stamp 的那部分（物理 cron / 人的动作）：它不由任何上游决定、上游 done 不保证它满足。
- **边 E** = 上游段自检落 stamp → 下游段触发器变为可触发 的一条连接。承载启动数据（小到一个 stamp、大到上游整批产出本体）+ 机械传导（stamp 就位 + 触发条件到点 → 下游跑），**边上零判断**。下游触发器何时满足只是**模式差别**（同一次执行内立刻 / 几分钟后 / 几个月后 cron），不改变「这是一条边」。

**读**：`02_verdict_cut.md`。

**做**：给每段 S 贴属性、抽边——
- **触发方式**：被什么唤起（cron / 状态 / 人 / 上游 stamp）。
- **外部支脚识别**：拆解每段触发器，标出其中非 stamp 的外部支脚。**含外部支脚的段 = 需配存活兜底边的候选**（第 3 步处理）；纯 stamp 驱动段不需要。
- **资源域 × 主体**：每段标〔执行主体：在场 / 无人值守〕×〔可写资源域：工作库 / 记忆池 / 身份层〕。
- **抽边**：每个时序断点 = 一条边 E（上游段 → 下游段）。所有段地位平等，区别只在触发方式；**一段被多条边指入是常态**（如 dream 被 daily 指入 + 被 week-sync 存活兜底边指入），不需任何特殊规则。
- **报告型探针 `report_probe`**：语料中「A 监视 B 的事件走向，异常**只报不驱动**」的关系（如 dream 校验漏账只报不补写）= `report_probe` 边（kind 枚举第四值）：登记 `watcher` / `watched` + 报告落点，**无驱动语义**。与 `survival_backstop` 的分界即在驱动位——backstop 监「没醒」且驱动补做；report_probe 监「走向异常」且只报。不登记则监视关系在拓扑里不可见；不得为凑驱动语义把 report_probe 硬写成 backstop。
- **同时并行分叉的两段**：各自独立标属性、各自一条入边；若汇合，汇合段被两条边指入（常态）。

**伪边剔除**：只有「时序相继」（上游 out → 下游启动）是 orchestrator 真要连的边。其余（共享判据 / 职责切分 / 横切派单）**不是段间的边，是各段各自指向权威源的指针** = meta-skill 第 4 步 index-mode，归 meta-skill 编段时处理，orchestrator 不碰。
- **禁 dispatcher 铁律**：语料无共同入口事件时，禁止臆造一个「判断分流」段把 N 个独立段挂到一个判定段下——共享判据是指针不是入口；「判断谁该跑」的职能属于人 + 调度层（harness），不进拓扑。语料**确有**共同入口（某物到达 → 判定类型 → 走 N 条互斥下游之一）才是判断分叉，照常每分支一条边。

**写**：`03_nodes_edges.md`（段属性 + 外部支脚标记 + 边清单）。

### 第 3 步 · 每段配尾审计 + 焊边（pull 三机制 · 零软边）

本步先就地钉死机制术语：
- **尾审计 sub-agent** = 段 S 结尾**强制调用**的独立 sub-agent：与主对话隔开、只读 out(S) 落盘文件审是否达标。达标 → 落 stamp；不达标 → bounce 回主对话强制重调 S（成 loop）。它**取代**旧「段自己检查自己」（自证有盲区）。
- **存活兜底边** = 仅为「触发器含外部支脚」的段配的一条边，来自**独立节律的下游**：该下游醒来扫此段 stamp，缺则驱动补做。纯 stamp 段不配。

**读**：`03_nodes_edges.md`。

**分配 ID（本步起始）**：为本次编译分配 `topology_version`（run-id：时间戳 / 单调计数器，全程恒定）+ 每条边一个 `edge_contract_id`（内容任一变即换新 id）+ 算一个 `edge_contract_hash`（对边契约内容的 canonical 指纹；边契约本步已成型，可算不死锁），写进 `04_nodes_edges.md`，随第 4 步规格包传 meta-skill 内嵌。（**解 P1 死锁**：最终版 skill 要内嵌 topology_version，故它必须第 4 步前就存在。）

**做（pull 三机制）：**

**机制一 · A 尾审计 sub-agent（取代旧「段自检」）**：每段 S 结尾强制调用一个独立 sub-agent——只读 out(S) 落盘文件审是否达标：
- 达标 → 落完成 stamp，A 段结束。
- 不达标 → bounce 回主对话，强制主对话重调 S、重走，直到达标（成 loop）。
- **空产出合法性必显式**：凡段产出天然可空（零毕业候选周 / 无工作日 / 零孤儿），尾审计达标标准**必须显式写明空产出算不算达标**——通常「流程真跑完 + 空结果有真依据」= 达标落 stamp，不 bounce；把「产出非空」误设为达标条件 = 零产出周期 bounce 死循环。标准含糊两读（「候选生成」读成「≥1 候选」）= 该段配置不合格、标红回本步。
- **为何独立 sub-agent 而非段自检**：生产者审自己有盲区（顺素材滑、证伪不了自己）；只读落盘文件 = 不碰生产时的脏 context。= meta-skill「编译者不自测」在网络层的复刻。
- **为何放 A 尾不放 B 头**：A、B 可隔数周，放 B 头则补做时 A 的上下文已冷；放 A 尾趁热审、产出还在手边。
- **out(S) 是判断分叉裁决时**（如审稿通过 / 打回）：每分支各一条边指向下游段。区分两种「往回」——**段内 loop** = 不达标、同段重做、不放行任何别的下游触发器；**回边** = 裁决放行**另一段**的下游触发器、跨段（如打回 → 退回写稿段），是正常的边（构成环也合法）。判据 = **有无放行「另一段」的下游触发器**。裁决段「达标」= 决定已做出（产出有效裁决），非「被裁决对象合格」。

**机制二 · stamp 多米诺（纯 stamp 链的存活，自然成立）**：上游 done 必落 stamp → 执行引擎据 stamp 拉起下游。纯 stamp 驱动链中间段的存活由此保证，无需额外哨兵——base case = 第一段根触发，必然触发的前提下多米诺自推。
- **stamp 物理形态要求（对所有 stamp 生效）**：每个 stamp 必须在本步定义一个**下游可扫到的物理落点**，形态四选一（不必是资源域独占文件）：(a) **交接件 / 会话头**——下游启动时读到的交接记录本身即 stamp（如 week-sync 每次开机报的简报 = 「我今天跑过」的痕迹）；(b) **现有文件内字段**（如 last_dream.md 一行日期 = dream 段 stamp）；(c) **独立标记文件**；(d) **临时落盘读后删**（下游读到 pass / no-pass 即删，只留一个真值）。**只读段**（不写记忆池 / 工作库 / 身份层内容）用 (a)/(d) 形态留 stamp，不违反其只读性。只有名字、连个可扫落点都没有的 stamp = 该边不合格，标红回本步补定义，不得带病进第 4 步。

**机制三 · 存活兜底边（仅为含外部支脚的段配）**：对第 2 步标出的「含外部支脚」段——它「压根没醒」这种故障，上游察觉不到（上游 done、stamp 在，但 cron 没 fire / 机器关着，该段照样没醒）→ 配一条来自独立节律下游的存活兜底边：该下游醒来扫此段 stamp，缺则驱动补做。
- **独立节律下游的选取**：优先挂在系统**最可靠的根触发器**上（系统为人服务 → 「人开机 / 到场」比机器 cron 可靠）。用最可靠节律监视次可靠节律。
- **驱动而不代写**：兜底下游若自身资源域受限（如 week-sync 只读、不写记忆池），它不亲自补做，而是**把「上游未完成」作为自己的入口阻塞，驱动上游段去跑**（上游自带写权限），上游落 stamp 后控制权回兜底下游续跑。守卫只挡住并驱动，不越权代跑。
- **探针类型 + 缺失分诊**：兜底边契约标 `probe_type`——`exact`（一条边只监一个被监视段的 stamp）或 `superset`（一个下游醒来扫多个上游 stamp，如 week-sync 扫 dream + daily 多个夜间 stamp）。superset 合法，但**监到缺失必须先分诊再驱动**：判定缺失的是哪个被监视段，只驱动真正没醒的那段，**禁止默认「根段没跑」直接驱动根段**（缺失可能是中间段挂了，盲驱根段会重复劳动或掩盖中间故障）。分诊判据 = 缺失 stamp 的段 id 与其上游 stamp 在否的联合判断。
- **孤立外部支脚段免配口径**：含外部支脚的段，若网内**无任何独立节律下游**可作兜底者（语料只有它自己一条链），则兜底边**合法免配**，不得臆造语料外的监视组件充数。但须在 topology.json 填 `liveness_gaps[]`（段 id + 免配原因 + 「部署期若引入独立节律下游须补配」），显式移交部署核。
- **覆盖面销账（对第 2 步全部候选逐段处置）**：每个「含外部支脚」段必须给出三选一**显式**处置——(a) 配驱动型兜底边；(b) 网内无独立节律下游 → `liveness_gaps[]` 免配登记；(c) 降级论证（该段漏跑可接受 + 依据，同样登记进 `liveness_gaps[]` 注明 accepted）。静默不配（既无边也无登记）= 本步 fail。`report_probe`（只报不驱动）不得充当兜底处置——兜底的定义在驱动位，提醒不是兜底。
- **兜底者单点正交**：兜底边的价值 = 节律独立。兜底者的触发节律不得与被监视段的外部支脚**共享同一单点**（同一个人的同一到场时刻 / 同一物理 cron）——共享单点则一处失效两段齐哑，兜底失效，视同未配。人在场类支脚的兜底优先挂**另一个**必到节律（如次日 / 周初开机）。
- **跨周期重汇合（周期段专项）**：周期性段（日级 / 周级节律）的兜底扫描必须能识别**跨周期缺失**（上一周期没跑，而非只看本周期窗口）并驱动补做；只扫当期窗口 = 上一周期漏跑静默翻篇，兜底覆盖不完整，标红回本步。

**边过两道并列检查（零软边）：**
- **检查一 · 启动数据够不够 trigger 下游**：out(上游) 启动数据足以让下游启动？足 = 合法；不足 → 标红「此边缺料」回上游确认。量依情况（stamp 类一个够 / 科研类要整批数据本体）。
- **检查二 · 零软边**：边走向必须是 out(上游) 的**确定函数** route(out(S))——机械算得出 = 硬边；要运行期人补一个不在 out(S) 里的输入才能定走向 = 软边，揪出编进确定性触发器；编不进 → 标红「此边悬空需人补」。**人在运行期做编排决策 = bug。**
- 两检全过 → 焊触发器：启动数据就位 + 触发条件到点 → 触发下游直接跑。

**写**：`04_nodes_edges.md`（尾审计配置 + 段内 loop + 边触发器 + 存活兜底边 + edge_contract_id）。**复审模式**：同时产 `03a_as_is_vs_should_be.md`（应然网段 / 边逐条比现网实然 → 现网边 / 应然边 / delta / 修复落点），强制交付。

> 三机制的完整落地范例（记忆系统）见 §附 B。

**做**：每段打包成「节点规格包」（§8 接口）外包给 meta-skill，段间彼此独立可并行。规格包**带全网络层边信息**（触发方式 + 外部支脚标记 + 触发前置 stamp + 出口 stamp + 各入出边 edge_contract_id + 本段是否为某存活兜底边的被监视方 / 监视方），meta-skill 据此**一次产出最终版** SKILL.md（触发层 description、入口守卫、出口 stamp 全编进正文；边契约 id / hash / version 由 meta-skill 网络节点模式转录进 frontmatter 三键——格式管辖在 meta-skill 侧，见 §8），走完自己的 1→9 步（含第 7 步触发 eval + 第 8 步检验，M6 闸在此逐段验声明格式）。**不留「编完再回填 description」的二次改动。**

### 第 5 步 · 组装入网 + 网络级六检 + 版本校验

**读**：`05_skills/` + `04_nodes_edges.md`。

**做（不改 description）**：第 4 步交回的已是最终版。本步只——
- **版本校验（防漂移）**：跑 `scripts/check_topology_version.py`，机械核对每份最终版 skill 内嵌的 edge_contract_id + topology_version 与 `topology.json` 逐条一致；不一致 → 回第 4 步带正确边契约重跑 meta-skill，不手改 skill。（七道断言 A-G 详义见 §9。）

**网络级六检**：派独立 sub-agent，逐项过——
- **① 边核验**：走向确定 + 启动数据足，无软边 / 缺料；**授权断点出口闭合**——每个授权断点的 verdict 各分支有归宿（下游段 / 显式 `resolution_pending`），悬空 = fail。【机械层】
- **② 版本 / 契约一致**：跑 `check_topology_version.py` 七道断言（A 版本 / B 边集 / C 两端 / D 契约 hash / E 内容重算 hash / F stamp 引用闭合 / G 正文标识符可解析；D+E 抓「ID 同、内容异」，F 抓契约引用悬空，G 抓正文幽灵引用）。【机械层】详义见 §9。
- **③ 正文 ↔ 契约语义闸**：机械闸只验「声明 vs 声明」（topology.json / frontmatter / hash 三处一致），验不出「正文实现 vs 边契约」是否相反 → 派独立 sub-agent 逐边读下游 skill **正文**，比对「触发条件 / 启动数据 / 判断段钩子」是否与 edge contract 同义。专查三类漂移：是否把**可缺失启动数据写成触发必需项**；是否把**内部判断分支写成边级触发**；是否正文出现与 contract 相反的分支。这是语义比对、非机械脚本能判，故派 sub-agent。【语义层】
- **④ 时序自检验收（同 tick 多触发排序）**：拓扑能机械回答「任意时间点 / 任意一组触发条件就位时，此刻该醒哪些段、按什么序」。同一 tick 多段触发时必须答得出序（答不出 = ④ fail 回第 0 步：该顺序在画图阶段就该标成顺序断点而非并发）。【机械层】
- **⑤ 网络 dogfooding + 存活覆盖面**：拆独立 sub-agent 跑全网，验段内 loop + 回边环闭合 + **存活兜底边在「上游没醒」故障态下真能驱动补做**；故障态注入两类——外部支脚失效（cron 没 fire / 人没到场）+ 兜底者与被监视段共享单点齐失效；并对账第 2 步全部「含外部支脚」候选段的三选一显式处置（配驱动边 / liveness_gaps 免配 / 降级论证），任一候选静默无处置 = fail；周期段验跨周期重汇合真补。【语义层】
- **⑥ 覆盖闭合（账实核对）**：拆独立 sub-agent 持 `01_flow.md` 语料事实清单逐条对账——每个事实必有唯一归宿（入段 / 三种排除之一 / 伪边剔除 / 禁 dispatcher / out-of-scope + `resolution_pending` / `liveness_gaps`，六选一 + 依据）。**任何无主事实 = ⑥ fail**：语料里的运转单元既没入网、也没排除论证、也没标 pending 的「静默丢块」在此抓死。退化合法，静默退化非法。【语义层】

> 机械层（①②④）谁跑都一样、客观背书；语义层（③⑤⑥）脚本判不了，必须派独立异族 sub-agent 盲查正文，判绿判红取决于独立性与执行体质量——这是本网络检验的核心分层。

**路由**：六项全绿 → 过；① fail 回第 3 步补边 / 揪软边；② fail 回第 4 步重编该段（F 型引用悬空回第 3 步改契约）；③ fail 回第 4 步重编（正文跟契约对齐）；④ fail 回第 0 步重画图定序；⑤ fail 按暴露是段 bug 还是边 bug 回第 4 或第 3 步；⑥ fail 回第 0 步补清单或回第 1-2 步给无主事实定归宿。**任一不过回流，不得原地改字。**

**写**：`06_check.md` + 汇出 `topology.json`（单一权威）+ 渲染 `topology.md`（人读视图，含 topology_version）。

# 第四部分 · 接口与机读

## §8 orchestrator ↔ meta-skill 接口

两层咬合的咬合面，糊了整张网编不出来。**分工原则**：orchestrator 预填「网络层信息」（meta-skill 看不见的邻居 / 位置 / 契约），meta-skill 自己锁「段内信息」（目标函数本体 + 四环链 + 判据）。

**管辖权分配（内容 vs 格式）：**
- **orchestrator 管内容**：哪些边、每条边的 edge_contract_id / edge_contract_hash / topology_version 值、触发前置、启动数据 schema——规格包逐条传值。
- **meta-skill 管格式**：这些值落进 SKILL.md frontmatter 的序列化形状（`topology_version` 标量 + `edges_in` / `edges_out` 的 `[id:hash]` 行内式）由 meta-skill 第 6 步「网络节点模式」条款硬性规定 + validate.py M6 闸逐段机械验——产出物的 ABI 焊在编译器里，不由规格包逐次传格式文本（逐次生成的包不当承重权威；防双权威；编译时早闸优于第 5 步组装晚闸）。
- **格式定义单一权威源** = `references/topology_schema.md §skill frontmatter 约定`；meta-skill 条款与 M6 闸、check_topology_version.py 皆为其执行端，不另立定义。
- 第 4 步出口硬检查只清点**内容**齐不齐（段目录 / 文件齐备），**不查格式**——格式红该在 meta-skill 第 8 步 M6 闸就地抓死，漏到第 5 步检 ② = M6 闸失效，属 meta-skill 侧 bug。

**orchestrator → meta-skill：节点规格包**（第 4 步每段一份，落 `05_skills/<段名>/_spec_in.md`）：
```
段 ID / 名称：
目标函数种子：    orchestrator 从网络尺度目标函数派生的一句话「本段为全局贡献什么」
                  （仅种子；本体由 meta-skill 第 1 步自己锁，orchestrator 不替它锁死）
触发方式：        cron 时刻 / 状态条件 / 人的动作 / 上游 stamp 就位
                  （meta-skill 据此写 description；description 通篇只列触发情景、不写「一句话干什么」，skill 身份靠 name 字段）
外部支脚标记：    本段触发器是否含非 stamp 外部支脚（物理 cron / 人的动作）；若含，标出哪条存活兜底边监视本段
存活兜底边角色：  本段是否为某条存活兜底边的「监视方」（醒来扫下游 stamp、缺则驱动补做、驱动而不代写）
入边（逐条）：    edge_contract_id + edge_contract_hash + topology_version + 上游段 + 触发前置（上游须落哪个 stamp）+ 启动数据 schema
出边（逐条）：    edge_contract_id + edge_contract_hash + topology_version + 下游段 + 本段须交付的启动数据 schema
段尾审计：        本段结尾强制调独立 sub-agent 审 out(S) 达标的标准（只读落盘）+ 不达标时 bounce 回主对话重调本段的 loop
                  （产出可空段必含空产出合法性口径——空结果达标不 bounce）

                  frontmatter 三键；格式管辖在 meta-skill 侧（第 6 步条款 + M6 闸），本包只传值、不传格式文本。
```

## §9 防漂移与版本校验（version / id / hash 三重 + 断言 A-G）

topology 要复制进每份 skill（frontmatter 三键），复制就有漂移风险。三重校验防漂移（同 meta-skill「防复制体」手段）：

- **`topology_version`** = 编译起始分配的 run-id（**不是**内容 hash——hash 要等内容产出才有，会让第 3 步拿不到、锁死流程）。第 3 步起始分配，全程恒定。
- **`edge_contract_id`** = 每条边一个版本 ID。
- **`edge_contract_hash`** = 每条边契约内容的指纹。

三者盖进 `04_nodes_edges.md`、每份最终版 skill、`topology.json` 三处同值。第 5 步检 ② 跑 `scripts/check_topology_version.py` 的七道断言：

| 断言 | 查什么 |
|---|---|
| **A 版本** | 三处 topology_version 一致 |
| **B 边集** | 边集闭合、三处边清单一致 |
| **C 两端** | 每条边上下游段两端声明一致 |
| **D 契约 hash** | 抓「edge_contract_id 没变、契约内容变了」这类 ID 同内容异漂移——靠 hash 不靠 id |
| **E 内容重算 hash** | 对每条边**从 topology.json 内容重算** hash，与内嵌 hash 比对（不止比三处内嵌值相等，而是验内容真一致） |
| **F stamp 引用闭合** | topology.json 内每条边的 `trigger_config` / `trigger_precondition_stamp`、每条 backstop / report_probe 边「扫描的 stamp」所引用的 stamp 名，必须解析到**某段 `out_stamp` 定义**（精确匹配段清单已声明的 stamp 名）；解析不到 = 引用悬空（拼法漂移如 `last_dream_daily_done` vs `last_dream.daily`，或引用了不存在的 stamp）→ F fail 退出非 0，回第 3 步改契约 |
| **G 正文标识符可解析** | 每份 SKILL.md **正文**引用的段 id / 边 id / stamp 名，必须解析到本跑 `topology.json` 已声明的定义；解析不到 = 正文在引用本跑不存在的段 / 边 / stamp（幽灵引用）→ G fail，回第 4 步重编该段。正则须处理复合 token 边界（`EC-E1-v1` 不拆解误报）与文件名词干排除（`last_dream.md` 的词干非 stamp 引用）——假阳性回脚本修，不回退人肉盲读 |

- **A-E 验「三处复制一致」，F 验「契约内部引用自洽」，G 验「正文引用落到实处」**——复制对了但指向不存在的名字，A-E 全绿也拉不起下游，故 F 单列；契约自洽但正文说着不存在的名字，前六道全绿仍是幽灵引用（v1.1 实测形态：正文引用本跑不存在的段边、byte-identical 复制模板漏改正文），故 G 单列，把「依赖人盲读检③抓悬空」降级为脚本客观跑。
- **canonical serializer**（E 的口径）：写进 `references/topology_schema.md`——边契约字段中 `edge_contract_id` 与 `edge_contract_hash` 排除在被 hash 内容外，其余字段按键名字典序、值 trim、UTF-8 NFC 归一后拼接算 SHA-256 取前 16 hex。

# 第五部分 · 约束与边界

## §10 蒸馏必转录条款（T 条款）

**存在理由**：蒸馏是有损压缩，最先丢的是**否定式守卫**——不承载快乐路径、只在故障态显灵的「非 / 不 / 禁」句（实证：同一份 spec，一端蒸馏把防护写进流程硬句、三跑段全对；另一端漏蒸、三跑 2/3 段触发写窄）。故此类条款不允许蒸馏器意译或压缩。

**入选判据**：spec 中**防止特定运行期故障（死锁 / 阻塞 / 盲驱）的否定式守卫条款**。不是「重要的都进」——肯定式流程蒸馏自然保真，进这里的只有「有损压缩下最先丢、丢了就产运行期故障」的那类。

**T 条款清单**（每条 = ID + 必转录核心句；蒸出的 SKILL.md 必须含与核心句语义逐点等价、且否定词显式在场的表述）：

- **T-1（防兜底死锁）**：被监视段的 stamp 是监视方的**检查对象，不是触发前置**——若把它当触发前置，则 stamp 缺时监视方不醒，而「那段没醒」恰是监视使命 → 死锁。
- **T-2（防合取写窄）**：多入边段**任一入边到达即醒，非合取**——严禁把多条入边写成「全部 stamp 到齐才启动」的 AND 守卫。
- **T-3（防可空阻塞）**：**optional 启动数据不阻塞下游**——契约标可空的启动数据，下游不得当作触发必需合取项；空值照常放行。
- **T-4（防空产出死循环）**：可空产出段的尾审计**不得把「产出非空」设为达标条件**——流程真跑完 + 空结果有真依据 = 达标落 stamp，不 bounce。
- **T-5（防盲驱根段）**：superset 探针监到缺失**必须先分诊再驱动**，禁止默认「根段没跑」直接驱动根段。

**机械验收（蒸馏出口闸）**：蒸 orchestrator 的 SKILL.md 交付前，逐条 T 断言在场——每条 T 的否定式关键词（T-1「不是触发前置」/ T-2「非合取」/ T-3「不阻塞」/ T-4「不 bounce」或「非空…不得」/ T-5「先分诊」）在 SKILL.md 正文中可 grep 命中（同义变体允许，但否定语义必须字面显式，不得只靠上下文推断）。任一 T 缺失 = 蒸馏不合格，回炉重蒸，不得手补。

**生效范围**：约束**蒸馏动作**（spec → orchestrator SKILL.md），对每次重蒸生效；同理级联至下游——orchestrator 调 meta-skill 编段时，规格包所含 T 语义（该段涉及的入边合取禁令 / stamp 检查对象声明 / 可空放行）同样要求段正文显式在场，第 5 步检 ③ 专查此三类即其运行期验收。

## §11 自指终止与共同天花板

**自指会停**：orchestrator 处理的对象是「边」，边的种类有限可枚举（`{normal, survival_backstop, back_edge, report_probe}`）。把「边」提为一等设计对象后网络层闭合；网络的网络仍是网络、边类型不变，orchestrator **自我适用**（它自己也是会建文件、要入网、被调用的东西）。两层够了：meta-skill 管段内、meta-orchestrator 管段间的边，self-applicable，不上爬。

**共同天花板**：应然层（这套流程）推导可闭合，但**实然鲁棒性只能靠拿真系统 dogfooding 撞出来**——骨架推不出运行期会撞什么。记忆系统是当前唯一纯样本，作为首个 dogfooding 标的（复审模式首跑）。

# 远景 · 运行期中心化 runtime（下一步迭代方向 · 当前 spec 不实现）

> 本节记录一个**已确认的架构迭代方向**（夏洛克 2026-07-08 拍板），**不改动 §1–§11 的当前流程**。当前 spec 产出去中心化的 skill 网络（§1：运行期 orchestrator 退场、调度烧进各 skill 触发器）；本节的中心化形态是**下一阶段目标**，待 topology 地基（切段刚性 + 完整自包含）夯实、转 MCP 阶段落地。现在只据本节把 topology 往「中心化就绪」方向锁，**不实现中心 runtime、不改现有五步流程**。

## 去中心化 vs 中心化 = 调度逻辑存放在哪（不是"要不要后台"）

两种架构底层**都需要一个后台 runtime**（定时触发 / 拉起会话 / 读写状态）——不存在「无需后台的自主运行」。真正的区别只有一个：**调度逻辑（edge / 触发条件 / 定序）存在哪、由谁读**：

- **去中心化（当前 §1）**：调度烧进每个 skill 自己（各 skill 自带「我何时醒、醒了查什么、跑完排下一个」）。topology 只作参考文档、运行时无人读；底层后台是「哑」的，被各 skill 分别使唤。
- **中心化（本节远景）**：调度全收进权威 topology，一个中心 runtime 读它统一调度；各 skill 退化成纯执行单元（只写「怎么做」、不写「何时被触发」）。topology 从参考文档升为**运行时中心权威**。

> 显形例：改「代谢从凌晨 3 点改 4 点 + 周一核对多查一个新增的月代谢」——去中心化要翻 4–5 个 skill 各改各的、易漏（散落调度对不齐 = 漏跑类故障的根）；中心化只改 topology 一处、skill 一个不动。

## 三个驱动

1. **跨端多形态**：topology 平台无关；各端按能力以不同形态接入（全能端 = skill + subagent + MCP；弱端 = 纯 MCP），共享同一份 topology、各端一个 runtime 读它落地。
2. **可维护 / 不混乱**：改一条调度关系只动 topology 一处；去中心化要翻多个 skill 触发器、易漏。
3. **edge 一处集中**：段间 schedule / orchestrate / edge 全在 topology 显式管，不散在各 skill。

## MCP 的角色：接入层 ≠ 调度层

MCP 是被动请求-响应协议（client 调、server 应），解决**跨端接入**（驱动 1），但**不白送主动调度**——server 不会自己半夜醒来跑代谢。中心化调度须在常驻 MCP server 进程里**额外内嵌一个主动 scheduler**（读 topology、到点触发、管 edge）。MCP server（常驻进程 + 跨端接入）是中心 runtime 最自然的宿主，但「转 MCP」给的是容器，「中心化调度」是容器里额外要装的那台 scheduler。

## 代价（须认）

中心化换来统一 / 可控 / 可维护，代价 = **运行时单点**（中心 runtime 挂则全端调度瘫）+ **须长期维护一个常驻服务**。二者是「要一处管全局」的必然伴生、非缺陷——收益与代价同一枚硬币两面。

## 分阶段路径（现在只打地基）

1. **现在（当前 spec）**：把 topology 做成**中心化就绪**——完整、自包含、声明式，自足到「一个只读 topology、不读任何 skill 正文的中心 runtime 能照它完整调度」（与 `memory_agent §记忆系统结构` 那句「须自足到零上下文 agent 仅凭本节能推导」同构）。此地基**去中心化也需要**（边契约 / 覆盖闭合都在要），故零浪费；切段刚性、topology 完整性即在打此地基。
2. **转 MCP 阶段**：常驻 server 内嵌主动 scheduler，实现中心化。
3. **过渡期**：claude code 端仍可跑去中心化 skill（现成 skill + cron 机制），但 topology 保持中心化就绪、不欠债。

## 落地时对当前 spec 的改动预告（现在不做）

真正实现中心化时，§1「运行期零 orchestrator 实体、编译期退场」从**唯一设计**松为**一种消费方式**——改为「topology 是核心资产，运行期两种消费：(a) 编成各端 skill 自主跑〔去中心〕 / (b) 中心 runtime 读 topology 调度〔中心化〕」。此为核心取向调整，待地基夯实 + 转 MCP 时一并做，**本轮不动**。
