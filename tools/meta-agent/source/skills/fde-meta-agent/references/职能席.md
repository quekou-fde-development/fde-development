# Reference · 职能席（domain seat）

**归属**：`fde-meta-agent/references/职能席.md`。**状态**：09.20 采用。功能席见上游 `enterprise-brain-v1/streams/09-meta-agent/references/功能席.md`（预留，未采用；**不随包发**，本包不含该件）。

职能席是一个域的常驻数字员工：域内快反、域内取证、域内落表。它不做判断，不做跨轮策略，判断向上交。09.16 十九席里的域席（`d_*`）与受限域席都属此类，未来大量增席也属此类。

## 一 · 职能席的定义边界

| 是 | 不是 |
|---|---|
| 一域一席，域由 `kb_prefix` + `workspace` + `landing_tables` 三者共同界定 | 跨域席（那是入口席 M1I 的事） |
| 快反三闸全过才作答，缺证据标 `UNVERIFIED` | 推断补白 |
| 域内落表：写本域 KB 写路径、本域 ArcuBase 表、本域工作区登记 | 写他域任何面 |
| 判断交 M3N、深度推理交 C1D、审批交 T2、域外交 M1I | 自行裁决 |
| 面向真人时提交审批并说明依据 | 代真人承诺或改动真人可见记录 |

这条边界表决定了六段里 ③④⑤ 的内容与 ⑥ 里非职责声明的措辞。

## 二 · 输入特化

在 `references/seat-spec.md` 五块之上，职能席对以下字段有硬要求：

| 字段 | 硬要求 |
|---|---|
| `identity.kind` | `domain_seat` 或 `restricted_domain` |
| `function.domain` | 非 null；`slug` / `label` / `role_id` / `isolation` / `kb` / `workspace` 全非空 |
| `function.params`（六维） | 全部六维在位；与同类席至少三维不同（机检） |
| `function.fast_response` | 三闸原样；`human_approval_does_not_follow_from_gate_pass=true` |
| `function.routing` | 五去向全部可解析为逻辑键：`parent` / `quick_lookup` / `escalation` / `out_of_domain` / `approval` |
| `permissions.kbWritePaths` | 恰为本域前缀下的路径，不含他域 |
| `permissions.workspace_access` | 本域工作区 `register_artifact_write`，其余工作区不授权 |
| `permissions.accessPolicy` | `domain_seat` → `all_team_members`；`restricted_domain` → `restricted` 且主体集合显式给出 |

两个现网实例的关键取值，作模板校验样本：

| 席 | `code` | `display_name` | `kb_prefix` | `workspace.permission` | `accessPolicy` | `isolation` |
|---|---|---|---|---|---|---|
| `d_people` | D-006 | 霍仙姑 | `/kb/人力/` | `register_artifact_write` | `restricted` | `derived_from_workspace` |
| `d_confidential` | D-008 | 半截李 | `/kb/机要/` | `register_artifact_write` | `restricted` | `derived_from_workspace` |

## 三 · 六段在职能席上的展开

### ③ 域段（承担主要信息量）

模板骨架，`{}` 由规格填入：

```
【本域】{domain.label}（{domain.slug}）。本体角色 {domain.role_id}。
【知识库】读：{kbPaths 逐行}。写：{kbWritePaths}（只写本域）。
【工作区】{workspace.display_name}（{workspace.ident}，{workspace.uuid}），权限 {workspace.permission}：
  登记本域产物，不覆盖他人已登记内容。
【落表】{landing_tables.domain_owned 逐表：name（app_id / table_id），必填 required_fields}
【快反三闸】条目存在 · 条目与问题匹配 · 条目带引用。三闸全过才作答；任一不过标 UNVERIFIED。
  三闸全过不推出可动真人世界，涉真人另走审批。
【升级路由】须判断 → {routing.escalation}；须深度推理 → C1D；域外 → {routing.out_of_domain}；
  快查 → {routing.quick_lookup}；审批 → {routing.approval}。
【上级】{parent}：组织归属、汇报去向、冲突裁决三义同归。
```

`landing_tables` 逐表列出 `required_fields`，因为这是职能席之间最可判的差异所在——两席若落同表同字段，即同席。

### ④ 席位特段

`domain_seat` 与 `restricted_domain` 各一条模板：

- **domain_seat**：全员可见。写「本席对全团队开放咨询；域外问题先转 {out_of_domain} 再答」。
- **restricted_domain**：受限。写「本席只对访问策略内主体作答；非主体询问一律回复无权限并转 {out_of_domain}；不透露域内条目存在与否」。最后一句是机要域的硬约束——否认与承认同样泄露。

### ⑤ 边约束

```
【允许回报目标】{routing 五去向 → 已解析 employee_id，逐行 code · 名 · id}
【ArcuBase】{landing_tables 逐表：应用 / 表 / 读|写}
reply-targets 为会话级平台能力，本名单在本席提示词中约束路由；不把它声称为员工级硬 ACL。
```

只列本席五去向，不列全员目录（09.20 变更，见 `references/prompt-segments.md §五`）。

### ⑥ 公共段

三段原文（注入防御 / 真人裁决与 STOP_REQUEST / 工作区与 KB 分工）+ 骨架四位短标签 + 非职责声明。`human_facing=true` 的职能席在真人裁决条加一句「面向真人的回复先过三闸再过审批路由」。

## 四 · 六维差异的机检（上游执行，非本包段闸）

六维差异是**上游批量闸，不在本包内**。执行体是 `enterprise-brain-v1/streams/04-skills/scripts/check_domain_differentiation.py`（09.13 已有，P1 复用并加第 4 条），它读全批
`seats/*.json` 两两比对；本 skill 一次只编一席，手上没有第二席可比，故结构上跑不了这条，包内也没有任何断言读它。下列四条描述的是那个脚本的行为，不是本包的段闸：

1. 读全批 `seats/*.json`，按 `(tier, kind)` 分组；
2. 组内两两比较六维，记录相同维数；
3. 相同维数 ≥ 4 即报 `DOMAIN_SEATS_UNDIFFERENTIATED`，列出两席与相同维；
4. 同 `kb_prefix` 的两席额外要求 `landing_tables.domain_owned` 的 `table_key` 集合不相交。

不达标的席位不进编制——**这道拦截发生在规格生成期，由上游脚本执行**。规格一旦递到本 skill，六维是否与别席重合已无从判断，`accept_spec` 不会因此停手。原因：两个职能相同的席位在运行期会互相抢答，且目录里无法区分。

## 五 · 模型与思考默认

| `kind` | 模型默认 | 思考档 | 备注 |
|---|---|---|---|
| `domain_seat` | 团队模型目录中的域席默认项 | 中 | 快反为主，深推交上游 |
| `restricted_domain` | 同上 | 中 | 与 domain_seat 同档，差异在访问策略不在算力 |

默认项从 `environment.model_catalog` 读取，不写死型号名。规格显式给 `model_policy.llmModelId` 时以规格为准。

## 六 · 面孔规则

| 情形 | 规则 |
|---|---|
| 与 09.14 已有人物同名 | `rule=reuse`，字节比对 `local_copy`，上传后像素哈希回读 |
| 新人物 | `rule=generate`，走 `references/image-handoff.md`：人物参考 + 两张系列参考，Codex 出图，QA 闸，上传回读 |

职能席用**人像**（09.14 系列），功能席用**符号图标**（09.16 SVG 管线）。两套风格不混用，因为详情页并列时人像与图标并存能一眼分出「域」与「位」。

## 七 · 单席产出与验收

一席编完，`readback.json` 里该行十六项全绿。人工只核对一处：详情页提示词格与 `effective-prompt.json` 同屏对照。其余项全由机检覆盖。

## 八 · 批量驱动（外层）

skill 一次一席。批由外层驱动：

```
for seat in seats/*.json (按 parent 拓扑序，根先):
    invoke fde-meta-agent(seat)
    if readback[seat].pass: append identities
    else: record blocker, continue（不回滚已过席位）
后处理: 对 UNRESOLVED 回报目标逐席补 PATCH ⑤ 段，各留 evidence
```

拓扑序保证多数回报目标在编本席时已可解析。`UNRESOLVED` 只在互为上下游的环里出现，补 PATCH 是对环的处置。
