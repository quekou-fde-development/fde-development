# 客户资料清单

[返回项目管理手册](../项目管理工作手册.md#stage-45) · [全部模板与参考](../README.md) · [调研方法论](../④调研/调研方法论.md)

## 这份表干什么用

进场调研之前，先让客户填一份最基础的情况。作用是认门：知道他们有哪些部门、做什么生意、现在用什么系统。进场以后这些就不用再问一遍。

**不要拿这张表摸底。** 客户填不出来的地方不追着问，进场自己看。

## 怎么交给客户

- **谁给**：销售或 PM，约调研时间的时候一起发过去。
- **怎么说**：「这份表就是先认认门，不知道的空着，别猜，我们进场再问。大概二十分钟能填完。」
- **什么时候要回来**：调研前一天。要不回来的，说明客户那边配合力度有限，提前知道比进场才知道好。

## 最省事的填法

先把营业执照拍张照发过来，第一部分就不用逐条填了；有现成的通讯录或组织图，第二部分可以跳过。

## 第五部分 · 现在的流程文件

这一块只问有没有、什么形式、还在不在用，不用发原件过来。

| 项 | 填什么 |
|---|---|
| 有没有现成的流程图 | 有／没有／记不清 |
| 是什么形式 | 纸质打印的／Visio／PPT／Excel／挂在墙上的／放在系统里的／没有正式文件 |
| 什么时候做的 | 哪一年，或者「忘了」 |
| 现在还按它走吗 | 完全按它走／大体按它走／早就不是这样了／没人看 |
| 谁保管这些文件 | 部门或人名 |
| 有没有成文的制度和作业指导书 | 有／没有；有的话大概多少份，放在哪 |
| 来了新人，怎么教他做事 | 有人带／看文件／自己摸索／没怎么教 |

最后两项看着和项目无关，实际有关：一个公司怎么把做法传下去，决定了它的规矩能维持多久。

## 第六部分 · 现在在用什么电脑系统

| 项 | 填什么 |
|---|---|
| 有哪些系统 | 名字写上。比如「用友 U8」「钉钉」「自己找人做的」 |
| 是什么时候上的 | 记不清就写「好几年了」 |
| 是谁家的、谁在维护 | 有售后电话就写上 |
| 日常还在用哪些表格 | 比如「排产用 Excel」「考勤用纸质」「仓库用本子记」 |
| 有没有上过但没用了的系统 | 有的话写名字，为什么不用了 |

最后一项看着多余，实际最有用：一个买了没用的系统，往往正好指着一件没做成的事。

## 收回来怎么用

| 填的东西 | 用到哪 |
|---|---|
| 第一、二部分 | 现场手册的「部门清单」「项目负责人」「管系统的人」三个参数 |
| 第三、四部分 | 「业务类型」参数；现场追业务流时当起点 |
| 第五部分 | 现场判断现有做法靠什么撑着 |
| 第六部分 | 现场问系统时的底稿，省一轮复述 |
| 第七部分 | 现场排部门顺序、估天数 |
| 第八部分 | 进场卡的「前置线索」栏，原话保留 |

**本表不替代现场取证。** 表里写的都是客户自述，一律标「口述」，进场要对着实物、单据、系统再核一遍。

**一处刻意的空缺**：本表不问「你们最痛的是什么」「每年损失多少」。这类事要现场看痕迹取证；客户自己说的进待核清单，不进问题清单。
