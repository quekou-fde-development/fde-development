# 方案审核与开发审核送审邮件

[返回项目管理手册](../../project-management-handbook.md#stage-46) · [全部模板](../README.md)

由项目经理向总架构师夏洛克邮件异步送审。先方案审核、后开发审核；材料可以并行准备，正式开发审核对应已通过的方案版本。手册和工具反馈使用[GitHub反馈入口](../../../../feedback/README.md)。

## 方案审核邮件

```text
主题：【项目编号】【方案审核】【版本】项目简称

项目与场景：项目编号、客户、期数、场景编号与名称
Arcubase：母项目与场景记录链接
方案版本及阅读入口：知识库中明确版本的方案文件链接
问题定义：客户卡点、经营意义与事实依据
产品定义：拟提供什么能力、怎样改善问题
场景基线与目标：量名、测法、现状来源、客户核对结果、目标水平
A组材料：本次版本的业务流程、整体架构及graph链接
范围、分期与报价：对应文件链接、价值依据和客户配合条件
请求审核：商业可行性及需要裁定的具体事项
未决事项：已知事实、假设、尚缺信息及影响
项目架构师：姓名
项目经理：姓名
```

方案文件在知识库，A组技术协作版本在项目GitHub；对应版本和链接随邮件关联，避免引用会变化的“最新版”。

## 开发审核邮件

```text
主题：【项目编号】【开发审核】【版本】项目简称

项目与场景：项目编号、客户、期数、场景编号与名称
Arcubase：母项目与场景记录链接
方案审核依据：已通过方案的版本、结论与附带条件链接
GitHub仓库及场景目录：……
送审版本：commit
项目架构师的技术可行性结论：数据、系统、人力、客户时间窗及依据
第一部分｜开发架构（A+B）：同一commit下的统一阅读入口
  A：业务流程、整体架构及graph；说明方案审核后的差异
  B：九份spec；标明数据结构、数据流、信息流及实现条件所在章节
第二部分｜独立开发计划：同一commit下的文件链接
  计划摘要：时间、人员、工具、预计token与费用、依赖和验证安排
请求审核：技术可行性及需要裁定的具体事项
本次变更／未决事项／未验证能力：……
项目架构师：姓名
项目经理：姓名
```

已发送邮件记为待审。项目记录保存实际审核状态及原文链接，知识库保存审核原件，GitHub保留被审技术版本。退回后按意见修改对应材料并重新送审；开发审核通过并落实启动与开工条件后进入开发。
