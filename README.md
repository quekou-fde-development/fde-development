# 缺口 FDE 开发规范

开发手册、配套工具和反馈入口集中维护于本仓库。

| 入口 | 用途 |
|---|---|
| [流程与开发手册](handbook/) | 先读 FDE 总流程，再读技术开发细则；调研输入与九份 spec 参照按任务使用 |
| [开发工具](tools/) | 按具体工具归拢的说明、源码、ZIP、使用条件与官方入口 |
| [反馈](feedback/) | 填写反馈、查看进度、追踪修改和验证结果 |

当前发布内容为 10.09.2 手册、调研空表、现成工具包与反馈入口。各工具的版本和使用条件见 [工具清单](tools/catalog.json)。项目架构仍按手册提交总架构师审核。

每个真实交付项目按[技术手册 §0、§5.1—5.2](handbook/development-handbook.md)与 Arcubase 母项目关联，先在 Arcubase 登记母项目与场景，再在本组织新建 private 开发仓库，仓库名采用“母项目编码＋客户名称＋期号”，在仓库下按场景编号分别建文件夹，登记后固定使用仓库名。项目经理先 push 开发架构（A：业务流程、整体架构图及 graph；B：九份 spec）和独立开发计划，再通过邮件异步送审；获批后在原仓库持续维护实现和测试产物。客户资料与凭据保留在获授权的项目范围内。

送审时每个场景只需 `workflow/`、`design/` 和 `plan/`；README 提供关联与阅读导航。审核通过后先建立 `releases/` 并开发，形成可测试版本后再建立 `tests/`，记录被测版本、测试结果、缺陷和复测。测试通过并完成技术复核、取得发布批准后上线，交接资料关联相应版本。开发实现按实际工具和框架组织，不统一要求建立 `src/`。

执行顺序：**Arcubase 登记 → 新建母项目仓库与场景文件夹 → Meta Workflow 产出文件组 A → Meta Spec 基于 A 产出文件组 B → 编制独立开发计划 → 将开发架构（A+B）和开发计划两部分送审。**

Arcubase 维护母项目、子项目（场景）、核心项目内容及实际推进记录。GitHub 项目仓库作为内部开发协作台，按场景保存开发架构、开发计划、代码、技术变更、测试与发布记录。具体项目内容、客户背景、调研原件和沟通解释在 Arcubase 维护，README 只保留标识、关联链接与开发目录索引。

修改共用规范时提交 Pull Request，说明变化、依据及验证结果。架构与正式方法变更由总架构师审核；开发计划模板随手册提供。
